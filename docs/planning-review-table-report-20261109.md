# 사용자 검토표 1차 구현·검증 보고서

이하 내용은 구현 완료 당시 기록이다. 이후 [실제 Gemini 시험·원문 감사](planning-review-live-results-20261109.md)에서7개 응답·Scope 유지 교정·검토표 내보내기를 확인했다. 기능 흐름 확인과 남은 의미 근거 보완점을 함께 기록하며, 아래 실제 호출0회는 구현 당시 관찰이다.

사용자가 승인한 범위는 지휘자·기획자의 신뢰성 보완과 사용자 검토표 첫 버전이다. 기존 비교6쌍에서 드러난 응답 잘림·근거 판단·범위 수정 분기의 한계를 보완하고, 사용자가 기획의 반영 위치와 남은 문제를 읽을 수 있도록 했다. 팀원·제품·웹 UI·변경 영향표는 구현하지 않았다.

## 구현

- 모델의 MAX_TOKENS/비정상 종료를 파싱 전에 확인하고 부분 응답을 완성본으로 사용하지 않는다. 오류에 단계·사유·부분 응답·후속 안내를 기록하고 제공된 실패 토큰을 남긴다. SDK는1시도, Reviewer 출력 한도는16000이며 자동 유료 재생은 없다.
- 새 검토는 요구별 정상·실패·확인 사례의 원문 줄을 분리한다. 저장 상태별 trigger와 대응 근거도 구분하고, 읽기 자체 예외를 뒷받침하지 못하는 문구를 보수적으로 차단한다. 근거·상태가 부족하면 사용자 검토표는 확인 필요다. 인용 존재 검증이나 문구 검사로 의미상 진실을 증명했다고 주장하지 않는다.
- `scopeDisposition`으로 기존 Scope 안에서 기획을 고칠 일과 실제 승인 범위를 바꿀 일을 분리한다. Controller 통합 시험에서 기존 Scope/기획v1 보존→기획v2 수정→최종 승인pending을 확인했다. 과거 미분류 Review는 보수적 기존 경로를 유지한다.
- `review-plan --output 새폴더`와 `report.userReview`를 제공한다. 원문·Markdown 검토표·JSON·완료/파일 해시를 추가 호출·승인/반복 예산 변경 없이 내보낸다. 오래된 출처, 중단 검토, 예전 세부 근거 없는 검토는 확정 판단에 재사용하지 않는다. 실제 승인 기록과 문서 판단을 구분한다.

[사용 안내](user-planning-review.md), [새 독서 목록 검토표](acceptance/planning-review-table-20261109/demo-bundle/review.md), [기획 원문](acceptance/planning-review-table-20261109/demo-bundle/plan.md)으로 결과를 확인할 수 있다. 예시는 TEST/STUB다.

## 검증과 보존

타입 검사와 전체155개 테스트가 통과했다. 새 시험은 응답 잘림/정상 완료·실패 토큰/부분 응답 보존·재생 금지·Scope 분기/실제 수정 흐름·읽기 예외 근거·필수 근거 누락·검토표의 네 상태·구버전/출처/중단 보호·덮어쓰기 방지·ADC 없는 live-config CLI 내보내기·진단 경계 검증을 확인한다. 역사적 비교의 독립 검증과 복사본 변조 탐지도 포함한다.

실제 Cloud의 승인된 재고/할 일 프로젝트를 새 검토표로 읽기 전용 내보내기했고, 승인 기록이 그대로 표시되는 것을 확인했다. 기존37개 파일은 체크포인트와 해시가 일치한다. 기존6쌍의 원자료·생성기·고정 입력·봉인 점수는 그대로이며 독립 검증이 통과했다. 새 기능은 새 독서 목록 fixture로 확인했고 이전 비교를 재생하지 않았다.

세부 결과·해시는 [검증 기록](acceptance/planning-review-table-20261109/validation.json)에 보존한다. 이번 변경의 실제 Gemini 요청은0회다. 구조화 응답 mock과 읽기 전용 호환성 검증이며 **새 프롬프트/응답 형식/출력 예산의 실제 Gemini 성공이나 품질 향상은 아직 확인하지 않았다.** Windows 실모델 재시험도 별도다.

## 다음 재개 시

현재 구현은 첫 사용자 검토표와 신뢰성 보완이다. 다음 우선순위는 새 사례를 사전 고정한 실제 Gemini 시험에서 출력 완료·근거 적합성·범위 내 수정이 개선됐는지 확인하는 일이다. 완료한 비교를 재실행하거나 기존 승인 프로젝트에 plan/resume/retry를 다시 실행하지 않는다. 필요하면 `review-plan`으로 읽기 전용 자료만 만든다. 변경 영향표·웹 UI·일반 채팅 수정 방식과의 새 비교는 별도 범위로 남긴다.
