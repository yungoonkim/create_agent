# 사용자 검토표·신뢰성 보완의 새 실모델 시험 계획

검토표 1차의 오프라인 구현 검증 뒤 실제 Gemini 응답 형식·완료 여부·근거·Scope 교정 흐름을 확인한다. 기존6쌍 비교와 독서 목록 fixture를 재실행하지 않는다. 이 계획은 시험 준비이며 실모델 합격 결과가 아니다.

## 사전 고정

| 항목 | 설정 |
| --- | --- |
| 새 기획 | 반려식물 물주기 기록, 실제 Writer부터 시작 |
| 교정 사례 | 개인 운동 기록, 공개 서버 전송을 넣은 고정 초안부터 시작 |
| 모델/인증 | Vertex AI Gemini3.8 Flash, ADC, iceu-songpa11/global |
| 반복/요청 | 각 최대2회, 전체 SDK 요청 상한11회(6+5) |
| 승인 | 격리 TEST/STUB Scope fixture만 사용, 실제 최종 승인 없음 |
| 보존 | 모든 요청/응답·종료 사유·사용량·버전·오류·검토표·해시·압축 |

[입력](../examples/planning-review-live/cases.json)과 [고정 해시/설정](../examples/planning-review-live/freeze.json)은 실제 호출 전에 저장한다. 생산 코드는 c7ad008의 검토표/신뢰성 구현을 그대로 사용한다. 이번 시험 도구는 생산 프롬프트/정책을 바꾸지 않는다. 식물 참고 기획은 dry-run에만 사용하며 live Writer에 정답으로 전달하지 않는다. 운동의 고정 초안과 고의 결함은 교정 시험의 입력이지 모델 생성 결과가 아니다. 검사표와 참고 답안을 특권 지시로 주입하지 않는다.

## 실제 결과의 확인 기준

1. Writer/Reviewer 응답이 새 스키마로 검증되고 정상 완료했는가. MAX_TOKENS·잘린 JSON·안전 차단·전송 실패는 성공으로 세지 않는다.
2. 요구별 정상 동작·실패/무변경 동작·확인 사례의 인용이 실제 해당 내용을 뒷받침하는가. 저장 상태 trigger와 대응 근거도 구분하며 손상 데이터와 읽기 작업 예외를 혼동하지 않는가.
3. 운동의 고의 결함을 찾아 승인 Scope 변경 대신 범위 내 기획 교정으로 처리했는가. 수정본에 제외 기능이 없어지고 기존 요구·제약도 유지됐는가.
4. 사용자 검토표의 출처/버전·표시·근거가 실제 기획/Review와 일치하며 실제 구현 시험·사용자 승인과 구분되는가.
5. 원래 Scope, 기존 `.adtf`, 과거 평가 결과가 보존되고 실제 호출·실패·불명 사용량이 빠짐없이 기록됐는가.

상태/버전/해시 등 자동 관찰값과 원문 적합성의 진행자 판단을 구분한다. 두 사례의 완료만으로 일반적인 품질 향상·챗봇 대비 우열을 주장하지 않는다. 추가 모델 채점은 없으며 사용자 승인도 대신하지 않는다. Scope 판단·질문·반복 한도·검토 실패는 그대로 남기고 유리한 결과로 교체하지 않는다.

## 시작/중단과 비용

실행 ID와 live 시작 예약을 먼저 기록한다. 체크아웃당 고정 시험의 live 실행은1회이고 SDK도1시도다. 인증/권한 실패는 남은 사례를 건너뛴다. 출력 파일·완료/실패·부분 응답을 삭제하거나 자동 유료 재시도하지 않는다. 고정 소스/입력/실행기가 달라지면 생성 전에 차단한다.

요금은 기존 공식 요금 스냅샷과 제공된 입력/응답/추론/캐시 지표로 소계를 산출한다. 없는 지표는 모름이며 청구액으로 단정하지 않는다. 모델 SDK 요청은 최대11회지만 그 횟수 자체가 청구 성공 횟수나 고정 금액을 의미하지 않는다.

## 현재 상태와 실행 경로

Cloud ADC refresh는 재인증 필요로 반환했고, 공식 Google HTTPS 로그인 브라우저 준비도 `Browser Use could not read requirements`로 실패했다. 토큰·인증 코드는 출력/요청하지 않았으며 모델 호출은0회다. 네트워크/TLS 보호는 유지했다.

이미 ADC로 성공한 PC에서 [실행 안내](../examples/planning-review-live/README.md)의 변수 없는 명령 한 번으로 새 시험을 수행하고 압축 하나를 전달할 수 있다. 원자료를 받은 뒤 안전한 압축 검사·해시 검증·진행자의 근거/교정 감사·사용량 보고를 마무리한다. 이 준비 완료와 실제 시험 완료를 구분한다.
