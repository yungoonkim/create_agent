# 검토 판정과 근거 표시 보완

작업 순서2번인 검토 판정 안정화를 구현했다. 별도의 변경 영향표(3번), 제품 구현, 팀원 실행은 착수하지 않았다. 저장된 주차 v2 응답만 오프라인 재생했으며 Gemini 호출0회다.

## 이번에 바뀐 동작

1. 같은 major/critical 지적의 반복은 `STOP_REPEATED_REVIEW_ISSUES`로 명시하고 `stopped` 상태로 멈춘다. 사용자 취향 질문을 만들어내지 않는다. 실제 제품 선호 질문은 기존 `REQUEST_USER_INPUT` 경로를 유지한다. 선택적 minor 제안만 반복될 때는 이 중단을 적용하지 않는다.
2. 과거 순번 기반 저장 검증 지적은 같은 ID만으로 동일 문제라고 단정하지 않는다. 같은 위치의 규칙 문자열까지 같아야 반복으로 분류한다. 규칙 순서를 바꾼 경우의 오탐을 막는다. 의미 동등성을 문자열로 추정하지 않으므로 표현이 바뀐 같은 문제까지 모두 식별한다고 주장하지 않는다.
3. 저장 검증의 로컬 근거 검사를 정책과 검토표가 공유한다. 개별 인용 또는 실제로 해당 규칙을 나열한 공유 그룹만 연결 근거로 사용한다. 그룹 설명에 이름을 언급한 것만으로 자동 연결하거나 빠진 인덱스를 채우지 않는다.
4. 검토표는 모델의 supported/해결 주장을 로컬 연결 검사와 분리한다. 공유 사례는 각 규칙에서 참조하고 실제 인용은 별도 절에 한 번 표시한다. 같은 ID에 현재 차단 사유가 있으면 이전 지적의 ‘해결 주장’ 옆에 함께 표시한다. 구조상 연결은 의미적 검증 완료를 뜻하지 않는다.
5. 예전 저장 상태가 `awaiting_user_input`이고 그 사유가 기존 코드의 반복 지적 중단인 경우, 상태 파일을 변경하지 않고 표시/nextAction만 기술 검토 보완(`review_correction`)으로 안내한다. 원본 기획·공식 Review·예산7/7회·반복2/2회·승인 기록은 그대로다.
6. CLI의 로컬 경로 누락·기존 경로/잠금·접근 거부·스냅샷/예산 무결성 문제를 안전한 코드와 경로로 보여준다. 임의 SDK 오류·헤더·인증정보·스택은 그대로 출력하지 않는다. 빈 디렉터리가 빠진 이전 데이터 ZIP 문제도 실제 누락 경로를 확인할 수 있다. 잠금이나 예약을 자동 삭제하지 않는다.

## 중복 문맥 축소

모델 전송에서 이전 Review의 반복된 인용문·저장 감사 표·수정 감사 안의 전체 baseline 본문을 중복 전송하지 않는다. 저장된 Review 전체는 유지하고 버전/출처 SHA-256, 원래 지적·제안·사용자 판단 플래그를 보낸다. Writer에는 로컬 저장/품질/보존 검사에서 나온 모든 미해결 항목을 `requiredCorrections`로 전달한다. Reviewer의 `previousIssueSources`, 현재/이전 실제 기획 줄, 승인 Scope와 원요구는 유지한다.

| 실제 주차 v2 요청의 DATA JSON | 이전 UTF-8 바이트 | 축소 후 바이트 | 감소 |
| --- | ---: | ---: | ---: |
| Writer | 73,026 | 27,711 | 62.1% |
| 일반 Reviewer | 109,118 | 61,230 | 43.9% |

이는 기존 요청 자료에 같은 축소 변환을 적용한 JSON 크기 측정이다. 새 실모델 토큰/청구액/기획 품질을 측정한 결과가 아니다. 과거 고정 실험은 새 축소 표현과의 차이를 검증한 후 원래 응답을 재사용하며, 원래 요청·응답 원자료는 바꾸지 않는다.

## 오프라인 재검증 결과

[새 검토표](acceptance/review-consistency-20261110/review.md)와 [재검증 기록](acceptance/review-consistency-20261110/recheck.json)은 별도 산출물이다. 입력은 원본 `parking-export-c7572906.tar.gz`(SHA-256 `a7d7aea9d3fac4b70f7b9a1265465b3bbe31ca09e9c21082512dacc1921c6385`)이며 원본31개 파일이 바뀌지 않았음을 확인했다.

- createdAt 규칙6은 모델이 supported/해결이라고 주장했지만 개별·공유 확인 근거가 없어 계속 차단한다. 그룹에6을 추가하거나 원문을 보정하지 않았다.
- memo 등 실제 공유 사례에 연결된 항목에는 그룹의 원문 인용이 표시된다. 전부 ‘근거 없음’으로 표시하던 문제가 해결됐다.
- 새 정책으로 평가하면 반복된 근거 누락은 기술적 중단이다. 기존 상태 파일의 `awaiting_user_input`을 바꾸거나 승인으로 승격하지 않았다.
- 브라우저 미지원 환경의 덮어쓰기 허용과 모호한 BroadcastChannel 잠금은 실제 v2에 남은 의미적 문제다. 새 프롬프트를 강화하고 [별도 교정 후보](parking-concurrency-correction-candidate-20261110.md)를 준비했지만, 이미 저장된 기획/모델 응답을 수정하거나 새 모델이 이를 잡았다고 주장하지 않는다.

검증: TypeScript typecheck 및 전체211개 오프라인 테스트 통과. 실제 응답 재생·그룹 연결 누락/인용 표시·순서 변경 오탐·minor/실제 사용자 질문 분리·Controller의 stopped 상태·오류 정보 마스킹·모든 미해결 지적 보존과 입력 크기를 확인했다.

## 다음 경계

현재 PC에서 다시 모델을 실행할 필요는 없다. 기존 세션을 그대로 유지한다. 코드 업데이트 후 `planning:session ... status/export`는 유료 호출 없이 새 표시를 확인할 수 있다. 질문·예산·반복 상태를 초기화하지 않는다. 공식 기획 v3 생성은 별도 실행 결정이 필요하며 이번 단계에 포함하지 않는다. 다음 예정 기능은 별도의 변경 영향표다.
