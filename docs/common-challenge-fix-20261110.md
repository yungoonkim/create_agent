# 공통 반례 Reviewer JSON 전송 보완

택배의 성공 후보가 공통 경로에 통합되지 않아 주차 시험도 구조화 반례 요청에서 API400으로 중단됐다. 공통 GeminiPlanningReviewer의 반례 요청에서 `responseJsonSchema`를 제거하고 JSON MIME을 유지한다. 택배 성공 후보의 필수 키/사례 필드/인용 최대8개 지침을 새 공통 시스템 지시문에 옮긴다. 일반 검토의 구조화 스키마는 유지한다. API가 오류 필드를 특정하지 않았으므로 모든400의 근본 해결이라고 단정하지 않는다.

반례 결과는 기존 parser, 실제 줄 인용, 저장 감사, 정책 검증을 통과해야 정식 Review가 된다. 누락 항목을 자동 채우거나 인용을 잘라내지 않는다. 실패는 기존 pass로 대체하지 않고 중단한다. SDK attempts1, 반례 최대1회 정책을 유지하며 자동 fallback 재호출은 추가하지 않는다.

과거 base prompt·후보·요청/응답 해시는 보존한다. 이전 택배 전용 실험 도구는 명시적 legacy bridge에서 새 공통 요청과 고정 요청의 model/contents/그 외 설정 일치를 확인한 뒤 고정된 옛 schema 요청을 재생한다. 이 bridge는 공통 실행 경로에는 없다. 과거 source freeze 도구는 계속 소스 변경을 거부한다.

주차 이어가기는 고정한 원본3회 기록에서 기획 v1·Scope·일반 검토 요청/응답을 읽는다. 일반 요청 전체를 비교하고 저장 응답을 재사용한다(새 사용량에 옛 토큰을 합산하지 않음). 반례는 원래 요청에서 schema 제거/공통 시스템 지침 변경 외의 차이가 없을 때 한 번만 보낸다. 시작 예약은 중복 호출을 막는다. 공식 Review와 정책 결과를 별도 복사본에 저장하며 Writer/최종 승인은 실행하지 않는다. 누적 상한은3+1/6회다.

오프라인 검증은 실제 택배 성공 응답을 공통 Reviewer에 재생해 검증 완료, 과다 인용9개 거부, 주차의 정확한 일반 응답 재사용, 잘못된 반례 응답 보존·실패, 중복 시작 거부, 차단 판정의 Review 저장을 포함한다. 이는 새 주차 요청의 실제 모델 응답이나 기획 품질을 보장하지 않는다. 준비 과정 Gemini 호출0회. Windows 안내는 [README-recovery](../examples/parking-planning/README-recovery.md)를 따른다.
