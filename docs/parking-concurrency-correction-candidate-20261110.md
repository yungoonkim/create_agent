# 주차 동시성 교정 후보 — 공식 기획안 아님

현재 주차 v2의30·186·202~204행은 BroadcastChannel 메시지를 잠금으로 취급하고, 미지원 환경에서 실제 덮어쓰기가 생길 수 있는 fallback을 허용한다. 기존 보존 요구를 완화하는 변경이므로 한계 설명만으로 통과시킬 수 없다. 아래는 후속 Writer가 검토할 **수동 분석의 교정 후보**이며, 기획 v3·실제 구현·사용자 최종 승인이 아니다. 원래 v2는 보존한다.

- 같은 origin의 모든 쓰기 탭이 공유하는 실제 배타 장치(예: 지원되는 브라우저의 Web Locks API)를 기획자 제안으로 명시한다. BroadcastChannel은 변경 안내용 메시지 수단으로 구분한다. 도구 밖의 임의 저장소 편집까지 막는다고 주장하지 않는다.
- 잠금 범위는 최신 저장값 읽기→현재 원본 검증→처음 읽은 상태와의 충돌 확인→변경 후보 구성/검증→직렬화/저장 성공까지다. 추가·수정·삭제·차 찾음·찾음 취소를 모두 포함한다. 잠금 경합 시 후행 탭은 변경된 원본을 확인한 뒤 입력을 보존하고 변경을 거절한다.
- 지원되지 않거나 잠금을 얻지 못하는 환경에서는 쓰기를 차단하고 입력·기존 값을 보존한다. 안전 보장을 포기한 재확인 후 쓰기로 fallback하지 않는다. 잠금을 기다리는 동안 오류·취소·탭 종료가 발생했을 때의 안내와 재개 경계를 명시한다.
- 변경 감지에 사용하는 값의 필드 위치·갱신 규칙을 구체화한다. 시스템 시각의 같은 밀리초나 시계 역행이 같음/최신 여부를 보장하지 않으므로 타임스탬프만으로 배타성이나 변경 감지의 완전성을 주장하지 않는다.
- 저장 성공 전 실패는 무변경 보존으로, 저장 성공 후 표시 오류는 이미 저장됐을 수 있는 상태로 구분한다. UI 오류를 이유로 성공한 저장을 자동 롤백했다고 말하지 않는다.
- 확인 사례는 A/B 동시 시작, 후행 탭 충돌 거절, 잠금 미지원/획득 실패, 찾음 취소 충돌, 저장 실패를 포함한다. 잘못된 createdAt 확인도 실제 잘못된 날짜 값을 넣어 별도 또는 적절한 공유 사례로 연결한다. 다른 필드가 잘못됐다는 이유로 정상 createdAt까지 검증했다고 주장하지 않는다.

이 후보의 근거는 승인된 원본 보존/다중 탭 덮어쓰기 방지 요구다. 브라우저 지원 범위 등 기술 제안은 최종 기획 검토 때 판단해야 한다. 이번에 제품 코드나 공식 기획을 새로 작성하지 않았다.
