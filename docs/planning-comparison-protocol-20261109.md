# 단일 작성과 ADTF 기획 과정의 비교 계획

기준일: 2026-11-09 (한국 시간). 사용자는 같은 모델·같은 요구사항으로 단일 작성과 ADTF 결과를 출처를 가려 비교하고, 중요한 원자료를 보존하도록 요청했다. 팀원 Agent·제품 구현·OpenAI API 추가는 범위 밖이다.

## 사전 고정한 설계

| 항목 | 계획 |
| --- | --- |
| 새 일상 주제 | 장보기 목록, 생활비 지출 메모, 주간 식단표 |
| 반복 | 주제별2회, 총6쌍 |
| 모델 | 양쪽 Gemini 3.8 Flash / Vertex AI |
| 동일 입력 | 요구 원문·Scope·미리 정한 TEST/STUB 답변·Writer 지침·출력 조건 |
| 출발점 | 한 번 생성한 최초 초안을 단일 작성 결과로 삼고 ADTF도 정확히 같은 초안을 재사용 |
| ADTF 과정 | 현재 코드의 Reviewer·반례 검토·정책·수정 루프, 평가에서는 최대3회 반복 |
| 기준 | 주제별9기준, 각0/1/2점·실제 근거 줄·판정 이유·중대 결함 |
| 주 평가자 | 현재 Codex 진행자. 익명 후보만 보고 점수 봉인 후 작성 방식 공개 |
| 지적/수정 감사 | 점수 봉인 후 검토 지적과 수정 전후 원문을 대조해 타당성·해결/미해결·퇴행 기록 |
| 호출 상한 | 생성54회. 선택적 Gemini 익명 채점6회·지적 감사6회까지 총66회 |

[입력](../examples/planning-comparison/cases.json), [고정 설정/해시](../examples/planning-comparison/freeze.json), [요금표](../examples/planning-comparison/pricing.json)를 모델 생성 전에 고정한다. 실제 사용자의 새 제품 Scope 승인으로 취급하지 않고 시험용 승인 fixture만 격리 저장한다. 최종 사용자는 자동 승인하지 않는다.

단일 작성도 ADTF의 충실한 Writer 지침과 확정된 요구사항을 받는다. 단순히 불충분한 프롬프트를 줘서 불리하게 만들지 않는다. 따라서 이 시험은 **검토·정책·수정 과정의 추가 효과**를 비교하며, 요구 질문 수집이나 승인 관리의 가치까지 측정하는 시험은 아니다. 첫 초안을 공유해 초기 샘플 차이를 줄였고, 물리적 첫 모델 호출은 한 번만 발생한다. 비교용 비용에서는 각 방식의 출발 비용으로 한 번씩 배분하되 전체 실제 호출 합계에는 중복 계산하지 않는다.

## 익명 평가와 판단 근거

후보에는 무작위 ID를 붙이고 작성 방식·버전·프로젝트 메타데이터·변경 요약을 제거한다. 제품의 요구·정상/실패 규칙·검증 예시는 유지한다. 제거된 줄 수·원문/익명 본문 해시·대응표를 보존한다. 평가자는 `blind/`만 읽고, 모델 판정·사용량·대응표를 보기 전에 점수를 봉인한다.

각 기준의2점은 명확하고 일관된 충족,1점은 일부 누락/모호함,0점은 누락/중요 모순이다. 양의 점수는 실제 비공백 근거 줄이 필요하고, 결함은 종류·심각도·이유를 기록한다. 누락은 없는 내용을 구체적으로 설명한다. 코드가 검사하는 것은 기준 커버리지·참조 유효성이며 의미상 올바른 채점 전체가 아니다.

동일한 익명 본문에 다른 점수를 주면 평가자 불일치로 표시하고 과정의 품질 향상으로 세지 않는다. 원래 점수는 고치거나 숨기지 않는다. 문체나 길이로 출처를 추측할 수 있어 완전한 이중 맹검이 아니다. 파일 접근을 보안상 차단한 설계도 아니므로, 먼저 볼 파일과 봉인 순서를 지킨 사실을 기록해야 한다.

진행자 한 명의 모델 기반 평가는 외부 사람 패널의 독립 검증이 아니다. 같은 Gemini의 추가 채점은 선택 사항이며 주 평가와 구분한다. 추가 모델 채점 결과도 주 평가 점수 봉인 전에 열지 않는다. 평가 후 이 사례에 맞춰 프롬프트·정책을 조정하면 다음 검증에는 새 사례가 필요하다.

## 비교할 결과

- **내용:** 기준별 누락·모순과 중대/치명 결함, 같은 쌍의 점수 차이, 개선/동률/퇴행. 중단된 ADTF 초안의 점수와 승인 단계 도달 여부는 따로 본다.
- **지적 타당성:** 구조화된 지적별 supported/unsupported/unclear를 실제 기획·Scope·답변과 대조한다. 모델 이슈, 품질 프로토콜, 저장 정책, 비차단 제안/질문을 구분한다. 지적 행 수는 고유 문제 수와 다르며 같은 문제가 반복될 수 있다.
- **수정 효과:** 타당한 지적을 수정 시도한 경우 실제 해결/미해결/퇴행/불명을 기록한다. 수정 후 기존 요구가 깨졌는지도 익명 품질 점수와 원문으로 대조한다.
- **완료/중단:** 승인 요청까지 도달했는지, 추가 사용자 입력·Scope 결정·한도·호출/형식 실패로 멈췄는지 보존한다. 실패를 결함 탐지나 품질 향상으로 세지 않는다.
- **비용:** 고유 SDK 호출 시도, 입력·응답·reasoning·캐시 토큰의 제공 지표, 호출 시간과 요금표 기반 소계. 실제 청구액이나 제공되지 않은 토큰은 추정하지 않는다. 진행자의 Codex 사용량은 이 API 원장에 포함하지 않는다.

자동 집계의 개선 쌍은 점수가 오르고, ADTF가 승인 요청에 도달했으며, 호출 실패와 치명적 결함이 없는 경우로 제한한다. 나머지 점수 상승은 별도로 보고한다. 중대 결함의 내용·새 퇴행은 합계 점수와 함께 사람이 최종 해석한다.

요금 스냅샷은 [Google Cloud 공식 표](https://cloud.google.com/model-garden/pricing)의 global on-demand Gemini 3.8 Flash 기준이다. 2026-12-31까지 입력100만 토큰당0.75USD, 출력(응답·reasoning)3.75USD, 캐시 입력0.075USD다. Batch/Flex·약정·크레딧·세금은 가정하지 않는다. 캐시 지표가 없으면 제공된 입력을 일반 요율로 계산했다는 가정과, 빠진 사용량 지표를 함께 표시한다. 실제 GCP 청구와 다를 수 있다.

## 기록과 재실행 방지

실행 ID별 폴더에 다음을 남긴다.

| 경로 | 내용 |
| --- | --- |
| manifest.json | 입력/코드/실행기/요금표 해시, 실행 환경, 원래 프로젝트 보호 스냅샷 |
| provider/ | 모델 호출 전 시작 기록, 실제 요청, 원모델 응답·사용량·버전·실패. 인증 헤더 제외 |
| usage.jsonl | 고유 호출 원장. 첫 초안 공용 비용과 ADTF 추가 비용·평가 비용 구분 |
| private/runtime/ | 격리한 TEST/STUB Scope·Plan·Review·정책·오류·승인 대기 이력 |
| private/pairs/ | 최초·최종 후보와 지적·수정 전후 원문 |
| blind/ | 출처를 가린 후보와 고정 평가표 |
| manual-scores.json | 공개 전 봉인한 주 평가·근거 |
| feedback-audits.json | 지적 타당성·수정 효과 감사 |
| private/mapping.json | 익명 후보와 실제 방식 대응표. 채점 전 열지 않음 |
| summary.json | 공개 후 비교. 원자료를 대체하지 않음 |
| artifact-manifest.json | 기록 해시. 원문 변조를 새 정상 상태로 덮어 승인하지 않음 |

완료·시작된 실행 ID와 유료 단계를 자동 재생하지 않는다. SDK 재시도도1회 시도로 제한한다. 원래 `.adtf`는 실행 전후 파일 해시로 보호하고 평가 메모리는 별도 폴더에 둔다. 다른 머신에서 결과를 채점할 때는 그 머신의 `.adtf`도 별도로 보호하며 사용자 PC의 이후 상태를 원격 확인했다고 하지 않는다. 새 실패와 중간 결과를 지우고 좋은 결과만 남기지 않는다.

결과는 압축 파일 하나로 전달할 수 있다. 평가 중 대응표·모델 판정은 열지 않고 점수를 봉인한 뒤 공개한다. 최종 원자료·평가표·대응표·해시·보고서를 함께 Git에 보존한다. 인증 파일·토큰·OAuth URL·HTTP 인증 헤더는 저장소에 넣지 않는다.

## 준비 시점의 상태와 실제 실행

현재 Cloud ADC는 재인증이 필요하고 공유 브라우저의 공식 Google 로그인 준비도 `Browser Use could not read requirements`로 실패했다. 인증을 우회하거나 사용자에게 토큰/인증 코드를 요구하지 않았다. 기존 ADC로 이미 성공한 사용자 PC에서 [일괄 실행 안내](../examples/planning-comparison/README.md)를 따라 모델 생성을 실행할 수 있다. 별도의 OpenAI API 사용료는 발생시키지 않는다.

오프라인 시험은 익명화·근거 검사·비용 계산·고정 입력·전체 가짜 실행/봉인/감사/공개·압축·변조 탐지를 확인한다. **Fake 결과를 실제 기획 품질 비교 결과로 보고하지 않는다.** 실제6쌍의 생성·익명 채점·지적 감사·비용 집계가 끝나야 ADTF의 이점에 대한 결론을 작성할 수 있다. 이 계획의 준비 완료와 실험 완료를 구분한다.
