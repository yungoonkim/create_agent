# Windows 압축 해제 경로 문제와 실행 패키지

2026-11-10 (한국 시간). 사용자가 main의 Download ZIP을 Windows 탐색기로 해제하면서 0x80010135/대상 경로가 너무 긺 오류를 보고했다. `C:\adtf`를 권했지만 다시 오류가 났다. 상대경로218자와 예상 전체244자 계산만으로 탐색기 호환을 단정한 안내는 충분하지 않았다. 실제 대상 전체 경로/추가 중첩/탐색기 내부 처리 조건은 화면만으로 확정하지 않는다.

검증 로그와 보호 해시는 [배포 검사 기록](acceptance/windows-run-bundle-20261110/README.md)에 남긴다.

## 변경

`scripts/create-run-bundle.mjs`와 [실행 ZIP](../downloads/README.md)을 추가했다. 기준 Git 커밋의 `src`, `examples`, TypeScript 설정, 잠금파일, 실행 회귀 검사를 allowlist로 수집한다. 깊은 `docs/acceptance`와 Git 메타데이터·node_modules·dist·기존 `.adtf`·인증 파일은 넣지 않는다. 원자료를 저장소에서 지우거나 평탄화하지 않았다. 원본 시험을 다시 호출하지도 않았다.

표준 ZIP STORE 형식·UTF-8 이름·고정 타임스탬프로 외부 압축 라이브러리 없이 재현 가능하게 생성한다. 경로 탈출/Windows 부적합 문자·긴 경로·링크/서브모듈·크기 초과를 거부하고 기존 출력도 덮어쓰지 않는다. 실행 ZIP은 `adtf-run` 한 폴더를 갖고 내부 최장 경로가73자다. 파일별 해시와 소스 커밋을 manifest에, ZIP 해시는 sidecar에 남긴다.

`src`·예제·lockfile은 원본 바이트 그대로여서 기존 택배 시험의 소스/입력/실행기/가격 해시를 유지한다. `package.json`은 과거 원자료를 요구하는 비교 검사6개와 전체 Git이 필요한 배포도구 검사2개를 제외하고 배포 명령을 제거한다. 실행 패키지 검사165개와 전체 저장소 검사173개를 구분한다. 의존성/모델/thinking/예산 변경은 없다.

## 검증과 한계

- 전체 저장소 타입 검사·173개 테스트 통과. 신규2개는 ZIP 표준 헤더/알려진 CRC, 경로 거부, 재현성, 해시/고정 소스·제외 대상을 확인한다.
- Python 표준 ZIP 읽기 도구로 독립 CRC 검사를 하고 별도 폴더에 압축을 해제했다. Linux에서42패키지 설치, 타입 검사, 실행 패키지165개 테스트와 택배 고정 응답 검토·수정·압축까지 확인했다. 고정 응답은 실모델 품질 근거가 아니다.
- 최초 Cloud 설치는 기본 npm 캐시 위치의 쓰기 제약으로 실패했고 `/workspace/scratch`의 별도 캐시를 지정해 설치했다. 사용자 PC의 Windows ZIP 오류와 다른 환경 문제이며 TLS/권한 정책을 완화하지 않았다.
- 기존 `.adtf`·시험 원자료·생산 소스의 전후 해시를 확인한다. 추가 Gemini/OAuth 호출0회다. 실제 Windows 탐색기/CLI를 Cloud에서 재현한 것은 아니므로 사용자 실행 결과로 마지막 확인을 이어간다.

전체 main ZIP에는 역사적 원자료가 계속 들어 있다. 사용자 실행에는 별도 실행 ZIP 다운로드를 권한다. 전체 기록을 확인하거나 전체 검사를 실행하려면 전체 Git 저장소를 사용한다. 배포 파일은 `bundle-manifest.json`의 특정 커밋에 고정되며 항상 최신 main이라고 단정하지 않는다.
