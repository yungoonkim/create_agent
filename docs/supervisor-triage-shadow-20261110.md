# Supervisor 중재 모의 평가 1차

작업4번의 첫 단계로, 사람이 작성한 중재 제안을 기존 Policy와 분리해 검사하는 오프라인 도구를 추가했다. 실제 중재 LLM이나 자동 실행을 추가하지 않았다. [사용법과 한계](../examples/supervisor-triage-shadow/README.md).

## 이번에 확인한 것

현재 Plan/Scope/Review 출처와 반복 수를 검사하고 Policy 결정을 먼저 고정한다. 입력 전체의 SHA-256과 각 문서 ID/버전을 남긴다. 원시 Review 지적뿐 아니라 저장·품질·보존 감사가 만든 지적과 질문·제안을 모두 고유 ID로 포함한다. 제안은 모든 지적을 한 번씩 다루고 실제 Plan 줄/Scope 항목 및 해당 지적을 인용해야 한다. 참조는 문서의 실제 텍스트와 연결된다.

누락/중복/알 수 없는 지적, 오래된 입력, 존재하지 않는 줄, 기술적 차단의 취향 질문 전환, 사용자 요청 없이 Scope 변경을 요구하는 제안, 임의 실행/승인 필드를 거부한다. 구조 검사 통과는 `structurally_valid_for_manual_inspection`이며 내용이 옳다는 판정이 아니다. 제안은 승인 대기·반복 중단 등 원래 Policy 결과를 바꾸지 않는다. 분류를 실행 명령으로 변환하는 경로는 없다.

현재 API는 `manual_fixture` 작성자만 받는다. SDK·모델·프롬프트·실모델 호출 상한을 가진 실행 경로는 없다. 승인된 Scope라는 사실은 호출자의 전제이며 이번 도구가 승인을 확인하거나 만들어내는 기능은 아니다. 해시는 변경 탐지이며 서명/출처 인증이 아니다. 이전 Review는 구조와 Plan 버전을 확인하지만 이전 Plan의 모든 인용을 새로 검증하는 별도 역사 감사는 아니다.

## 실제 주차 자료의 재생

고정 SHA-256의 원본 archive를 임시 복사본에서 읽었다. 원시 Review issues는0개지만 `storage:issue-storage-validation-6`을 모의 평가 입력에 포함했다. 이는 createdAt의 모델 supported 주장과 실제 개별·공유 확인 사례 연결이 맞지 않는 문제다. 사람이 작성한 재검토 초안1개는 구조 검사를 통과했고, 잘못된 제안6개는 거부했다. **7/7은 모의 계약 사례 수이며 유료 요청 수가 아니다.**

원래 Policy는 `STOP_REPEATED_REVIEW_ISSUES`를 유지했다. 원본31파일 해시, 누적 모델7/7회와 기존 승인 상태는 그대로다. 추가 모델 호출0회다. 모든 입력·제안·거부 예시·출력과 내부 manifest를 [평가 archive](acceptance/supervisor-triage-shadow-20261110/offline-evaluation.tar.gz)에 보존했다. [요약 결과](acceptance/supervisor-triage-shadow-20261110/report.json), [archive 해시](acceptance/supervisor-triage-shadow-20261110/manifest.json).

## 해석과 다음 판단

222개 전체 테스트에 데이터 손실 지적, Reviewer의 범위 밖 SMS 요구, 사용자 명시 요청, 실제 질문, 정상 승인 대기, 반복/한도 유지, 지적/인용 위조, 실제 주차의 로컬·품질·보존 지적 누락 검사를 포함했다. typecheck와 전체 검사는 통과했다. 별도 추출한 실행 패키지도 typecheck와203개 테스트를 통과했고180개 파일 해시를 확인했다. 의존성 변경은 없으며 같은 잠금파일의 기존 node_modules를 연결해 검사했다. 과거 원자료가 필요한 평가 명령은 실행 패키지에서 제외했다. [검증 기록](acceptance/supervisor-triage-shadow-20261110/verification.json). 이들은 공개 수동 fixture와 저장된 응답의 계약 검사이므로, 중재자의 의미 분류 정확도나 기획 품질 향상·시간/비용 절감을 입증하지 않는다. 그 수치는 null로 기록했다.

실모델 시험은 별도 작업이다. 새 호출 상한과 모델/프롬프트를 정하고 독립 주제에 사람이 먼저 기대 결과를 작성한 후, 불필요한 질문·잘못된 재작업·Scope 확장·중요 결함 누락·인용 관련성·추가 비용을 비교해야 한다. 현재 소진된 주차 세션을 유료 재실행하거나 공식 Review를 덮어쓰지 않는다. 내용의 의미를 평가하는 도구가 아직 없으므로 구조 검사 통과만으로 중재를 제품 실행에 연결하지 않는다.
