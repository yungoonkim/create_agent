# 택배 수령 기록 기획
PARCEL-1 정상: 비공백 내용 이름, 실제 YYYY-MM-DD 예정 날짜, 선택 메모를 고유 ID/seq와 received=false로 등록한다. 같은 내용도 독립 기록이며 과거·오늘·미래 날짜를 모두 허용한다.
PARCEL-1 실패: 공백 이름·존재하지 않는 날짜는 안내하고 입력·목록·저장값을 바꾸지 않는다.
PARCEL-1 확인: 책/2026-11-10을 두 번 추가하면 미수령 기록 두 건이다. 공백 이름과 2026-02-30은 추가되지 않고 입력은 남는다.
PARCEL-2 정상: 선택 ID 한 건의 received 불리언만 받음/미수령으로 전환한다. 이름/날짜/메모 수정은 등록과 같은 규칙이며 ID/seq 불변이다. 삭제는 확인 후 한 건이다.
PARCEL-2 실패: 잘못된 수정·삭제 확인 취소는 입력·목록·저장값을 보존하고 쓰지 않는다.
PARCEL-2 확인: 같은 책 두 건 중 첫 건만 받음으로 바꾸고 미수령으로 되돌린다. 둘째 삭제를 취소하면 두 건 모두 남는다.
PARCEL-3 정상: 같은 origin/프로필로 다시 열면 정상 목록·received·seq 순서가 유지된다.
PARCEL-3 실패: getItem 자체 읽기 예외는 안내·무쓰기·변경 차단이며 쓰기 실패는 입력·목록·저장값 보존이다.
PARCEL-3 확인: 두 건 등록하고 첫 건을 받음 처리한 뒤 다시 열면 그대로다. getItem SecurityError면 무쓰기 차단, setItem 실패면 이전 화면과 새 입력을 유지한다.
공통 검증표: 단일 키 parcel_data에 schemaVersion:1,nextSeq,items[{id,seq,name,date,memo,received}]이다. 로드와 전체 후보 모두 루트/필드 타입·고유 ID/seq·양의 안전 정수 seq·nextSeq > max(seq)·비공백 name·실제 date·문자열 memo·불리언 received를 검증한다.
getItem이 정확히 null인 경우만 최초 실행으로 빈 메모리를 구성하며 첫 변경 전 빈 쓰기는 하지 않는다.
기존 빈/공백·깨진 JSON·미지원 버전·필드/값 위반은 원본 그대로 보존·무쓰기·변경 차단이며 자동 초기화나 백업 이동은 하지 않는다.
유효 데이터 조건은 공통 검증표의 모든 필드·값 검증에 통과한 JSON이며, 그 경우에만 로드하여 목록을 표시한다.
getItem 자체 SecurityError 예외는 원본 보존·무쓰기·읽기 실패 안내·모든 변경 차단이다.
전체 변경 후보에 공통 검증표를 적용하고 직렬화한 뒤 setItem 성공 시에만 메모리/화면을 확정한다. 실패는 입력·목록·기존 저장값 보존이다.
저장 후 UI만 실패하면 저장 취소라고 하지 않고 새로고침을 안내한다. OS/전원 장애까지 영구 보장하지 않는다.
http://localhost:4173/같은 프로필에서 Web Locks를 편집 탭 수명 동안 유지하고 획득 후 최신 로드한다. 비소유/미지원 변경 차단, 소유 탭 종료 후 새로고침한다.
로그인·외부 서버·운송장 조회·알림·공유·공개 순위·실제 제품/팀원 실행·실제 사용자 승인은 제외한다. 이 문서는 미승인 시험 후보다.
공통 검증 확인: 저장 JSON의 received를 문자열 "받음"으로 바꾸거나 name을 공백으로 바꾸고 로드하면 원본 보존·무쓰기·변경 차단이다. 같은 잘못된 후보도 쓰기 전에 거부한다.
