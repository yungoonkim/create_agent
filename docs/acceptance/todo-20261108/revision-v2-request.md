v2는 Reviewer pass였지만 진행자 내용 점검에서 아래 미해결 사항을 발견했다. 승인 Scope v6·사용자 답변 10개를 그대로 유지하며 기획 v3를 수정하라. 이 요청은 Reviewer 자체 revise가 아니라 진행자 품질 보완이다. 기존 버전을 덮어쓰지 말고 요청별 반영 내역·구체적 수락 조건을 적어라.

1. 범위를 단순하게 유지한다. 사용자가 요청하지 않은 ‘[기한 경과]’ 표시나 현재 시각 비교 기능 제안은 제거한다. 과거 마감일도 그대로 등록 가능하고 날짜/시간을 기록·표시만 하는 설계로 제안하라. 알림·기한순 정렬·검색·로그인·원격 동기화는 추가하지 않는다.
2. 제목·마감일시 필수/메모 선택, 날짜+시간, 삭제 확인은 실제 사용자 확정 선택이다. 그 외 설계는 최종 승인 받을 제안으로 표시한다. 사용자 흐름이 문서 맨 앞에 오며 기술 절은 뒤로 분리한다.
3. 마감일시는 시간대 없는 달력 날짜+시·분 값으로 한 가지 정규 형식(예: YYYY-MM-DDTHH:mm)으로 저장·표시하라. 입력 폼에서 값이 없는 날짜/시간을 거부하고, 지원 연도 범위(예: 0001~9999), 윤년 포함 실제 존재하는 날짜, 시 00~23/분 00~59를 명시하라. UTC/시간대 변환이나 현재 시각 판단은 하지 않는다. 표시만 다른 포맷을 쓸 경우 숫자 의미가 유지되게 한다.
4. createdAt 시각 우선 정렬은 PC 시계를 뒤로 돌리면 나중 등록한 항목이 앞에 나오는 결함이 있다. 순서는 등록 성공 시 부여하는 영속 단조 증가 순번을 유일한 기준으로 하라. 수정/완료/취소/삭제로 기존 순번을 바꾸지 않으며 새 등록은 마지막 순번보다 커야 한다. 동일 제목·같은 시각·시계 역행·재시작 뒤에도 원래 등록순을 지키는 예제를 넣어라. 순번/카운터는 안전한 정수·고유성·범위/증분 한도를 검증하고 넘으면 무변경 오류로 처리한다.
5. 저장 데이터 envelope(예: schemaVersion, nextSequence, items)를 명확히 제안하고 로드 시 배열 여부, 필수 키·타입·값, 제목 공백, 메모 문자열, 유효한 필수 마감일시, 실제 boolean, ID 고유성, 순번 고유성, nextSequence와 항목 최대 순번의 관계를 검증하라. 모르는 버전이나 손상 필드를 임의 보정/덮어쓰지 말라. 항목이 없는 유효한 저장 데이터와 저장 키 자체 부재를 구분한다.
6. 첫 실행은 localStorage.getItem(key)===null인 키 부재일 때만 빈 목록이다. 빈 문자열(''), 잘못된 JSON, null JSON, 잘못된 객체 등은 기존 손상 데이터이므로 빈 목록으로 취급하거나 자동 초기화/덮어쓰지 않는다. 읽기 접근 예외도 별도 오류로 처리하고 쓰기를 차단한다. 손상 데이터는 임의 수정·삭제하지 않으며 경고하고 등록/수정/완료/취소/삭제를 막는다. 실제 복원/백업 도구를 새 기능으로 추가하지 않는다.
7. 저장은 전체 목록+카운터를 하나의 JSON 문자열로 단일 고정 키에 한 번 setItem하는 경계를 명확히 하라. 후보 생성·검증·직렬화·setItem 전/호출 실패면 기존 저장값과 확정 화면 상태를 유지하고 입력을 보존한다. setItem 정상 반환이 commit 경계이며 그 뒤 화면 렌더링 실패는 저장 자체를 되돌렸다고 주장하면 안 된다. 저장은 됐지만 화면 갱신 실패라는 안내와 같은 주소 새로고침 후 복원을 명시하라. 전원 단절·물리 장애 무손실 보장과 혼동하지 않는다.
8. 저장 데이터 지우기 한계는 단순 이미지 캐시 삭제와 구분하여 ‘쿠키 및 사이트 데이터 삭제/이 사이트 저장 데이터 삭제’라고 정확히 설명하라. 같은 브라우저·프로필·일반 창·동일 origin(프로토콜/호스트/포트)의 고정 주소를 사용하도록 제안하라. file:// 직접 열기의 동작은 브라우저별 차이 때문에 보장하지 않는다. 실제 고정 주소 페이지 제공 방법은 향후 작업 지시에 명시하며 이 세션에서 서버 실행/제품 구현하지 않는다.
9. 지원 운용은 단일 탭의 순차 편집으로 명확히 한정한다. 단순 storage 이벤트 안내만으로 여러 탭 덮어쓰기가 방지된다고 주장하지 말라. 외부 변경을 감지했다면 변경 동작을 막고 새로고침으로 재검증 후 편집하도록 기술할 수 있지만 이벤트 지연/동시 쓰기의 트랜잭션 락이나 다중 탭 안전성을 보장하지 않는다. 실시간 동기화/잠금 기능을 범위 확장하지 않는다.
10. 앞서 요청한 동일 제목 중 특정 ID 하나만 변경, 삭제 확인 취소 무변경, 필수값/날짜 오류 무변경, 저장 실패 시 성공 표시 금지/입력 유지, HTML 형태 입력을 글자로 표시하는 기준을 유지하고 수락 조건에서 누락하지 말라.

Reviewer는 v1/v2 pass를 근거로 재통과시키지 말고 이번 수정 요청 각 항목을 실제 문구와 수락 조건에 대조하라. 이번 기획은 최종 사용자 승인 전 후보이며 실제 구현·테스트 성공·팀원 실행을 주장하지 않는다.
