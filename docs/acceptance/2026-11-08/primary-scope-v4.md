# 승인된 재고·유통기한 인수시험 Scope

- 프로젝트: `supervisor-gemini-acceptance`
- Scope: `scope-v4` / 버전 `4`
- 상태: 사용자가 채팅에서 승인했고 해당 결정을 저장했다. 기획안 및 팀원 실행 승인과 별개다.
- 생성 시각: `2026-11-08T09:40:44.375Z`
- 입력: 시험 진행자가 문서의 재현용 시나리오를 답변했다. 이 답변은 사용자 승인 기록이 아니다.

작은 매장의 점주 1인이 로컬 환경에서 로트(lot) 단위로 재고 및 유통기한을 안전하게 기록·조회할 수 있는 Node.js CLI 도구의 상세 기획 및 작업 지시서를 한국어로 수립한다.

## 필수 기능

- **REQ-01**: 고유 lotId, 상품명, 수량, 표시용 단위, YYYY-MM-DD 형식의 유통기한을 입력받아 신규 lot을 등록하는 기능 (lotId 중복 거부, 빈 문자열 거부, 등록 수량은 0 이상의 안전한 정수 보장)
- **REQ-02**: 특정 lotId에 대해 정수 증감량(양수/음수/0 허용)을 입력받아 수량을 갱신하는 기능 (존재하지 않는 lotId나 변경 후 결과 수량이 0 미만 또는 안전 정수 범위를 벗어나는 경우 오류 처리 및 기존 상태 유지, 증감량 0은 수량 유지)
- **REQ-03**: 전체 재고를 lotId, 상품명, 수량, 단위, 유통기한 항목으로 표시하는 기능 (수량이 0인 lot도 목록에 유지)
- **REQ-04**: 명시된 기준일(YYYY-MM-DD, Asia/Seoul 달력 기준)과 0 이상의 안전한 정수 N을 입력받아 유통기한 만료(유통기한 < 기준일) 및 임박(기준일 <= 유통기한 <= 기준일+N일) 목록을 구분 조회하는 기능 (수량 0인 lot 제외, 유통기한 오름차순 및 동일 날짜는 lotId 오름차순 정렬, 계산 결과 지원 날짜 범위 초과 시 거부)
- **REQ-05**: 로컬 UTF-8 JSON 파일에 영속화하며 재실행 시 데이터 유지, 임시 파일 후 원자적 교체(atomic rename) 방식 저장 및 잘못된 날짜/파일 손상/읽기/쓰기 오류 시 명확한 보고와 기존 파일 임의 초기화/덮어쓰기 방지 기능

## 제외 기능

- **EXC-01**: FEFO(선입선출/유통기한 우선) 자동 출고 및 자동 차감 기능
- **EXC-02**: 별도 폐기 처리, 폐기 사유 기록, 감사 이력 보존 및 별도 폐기 상태 필드 저장
- **EXC-03**: 실사 보정 workflow, 별도 lot 삭제/수정 workflow, 텍스트 검색 기능
- **EXC-04**: 바코드/QR 코드 스캔, 카메라 연동, 외부 POS 및 엑셀 연동
- **EXC-05**: SMS, 카카오 알림톡, 이메일, 모바일 푸시 등 외부 알림 발송 기능
- **EXC-06**: 사용자 로그인, 계정 및 역할/권한 구분, 다중 사용자 및 동시 writer 지원
- **EXC-07**: 웹/모바일 UI, 클라우드/서버 저장, 다중 기기 동기화, 배포 파이프라인 구축
- **EXC-08**: 결제, 발주/거래처 관리, 매출 통계 기능 및 단위 자동 변환 기능

## 제약

- 런타임 환경은 Node.js이며 구현 언어는 TypeScript strict 모드를 적용한다.
- 데이터 저장은 로컬 단일 UTF-8 JSON 파일을 사용하며 단일 프로세스 순차 실행 환경을 전제한다.
- 수량 및 N 값은 JavaScript 안전 정수(Number.isSafeInteger) 범위 내 0 이상의 정수여야 하며, 소수·NaN·무한대·음수 재고 결과는 거부한다.
- 날짜 처리는 PC 시스템 시각에 의존하지 않고 명시된 YYYY-MM-DD(Asia/Seoul 달력 기준)를 기반으로 검증 및 계산한다.
- 모든 기획 문서, 작업 지시서 및 CLI 출력/오류 메시지는 한국어로 작성한다.
- 본 인수시험 세션 중에는 실제 제품 코드 구현 및 팀원 Agent 실행을 진행하지 않으며, 지휘자 단독의 기획 및 작업 지시 수립만 수행한다.
