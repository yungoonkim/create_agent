# 프로젝트 기획안: 매장 재고 및 유통기한 관리 CLI 도구

- **프로젝트 ID**: `supervisor-gemini-acceptance`
- **기획안 버전**: v1 (Draft)
- **기반 승인 범위**: `scope-v4`
- **목표**: 작은 매장의 점주 1인이 로컬 단일 환경에서 로트(lot) 단위로 재고 및 유통기한을 안전하게 기록·조회할 수 있는 Node.js CLI 도구의 상세 구현 계획 수립

---

## 1. 범위 요약 및 경계

### 1.1 승인된 필수 기능 (In-Scope)
- **REQ-01 (신규 lot 등록)**: 고유 `lotId`, 상품명, 수량, 표시용 단위, 유통기한(`YYYY-MM-DD`) 등록. 중복 `lotId` 및 빈 문자열 거부, 수량은 0 이상의 안전한 정수 보장.
- **REQ-02 (수량 증감)**: 특정 `lotId`의 수량을 정수(양수/음수/0)로 증감. 결과 수량이 음수이거나 안전 정수 초과 시 오류 반환 및 기존 데이터 보존. 증감량 0 입력 시 기존 수량 유지.
- **REQ-03 (전체 재고 조회)**: 등록된 전체 lot 목록 표시 (`lotId`, 상품명, 수량, 단위, 유통기한). 수량이 0인 lot도 목록에 유지.
- **REQ-04 (만료/임박 조회)**: 입력받은 기준일(`YYYY-MM-DD`, Asia/Seoul 달력 기준) 및 정수 `N`(0 이상의 안전 정수)을 기준으로 분류.
  - 만료 목록: `유통기한 < 기준일`
  - 임박 목록: `기준일 <= 유통기한 <= 기준일 + N일`
  - 수량이 0인 lot은 조회에서 제외.
  - 정렬: 유통기한 오름차순, 동일 날짜는 `lotId` 오름차순.
- **REQ-05 (로컬 영속화 및 원자적 쓰기)**: 단일 UTF-8 JSON 파일에 저장. 임시 파일 작성 후 원자적 교체(`atomic rename`) 방식으로 저장 실패 시 데이터 오손 방지. 파일 손상/오류 시 원본 유지 및 한국어 오류 출력.

### 1.2 명시적 제외 범위 (Out-of-Scope)
- FEFO(선입선출) 자동 출고 및 자동 차감 (`EXC-01`)
- 별도 폐기 처리 workflow, 폐기 사유 기록, 감사 이력 보존, 별도 상태 필드 (`EXC-02`)
- 실사 보정 workflow, 별도 lot 삭제/수정 기능, 텍스트 검색 기능 (`EXC-03`)
- 바코드/QR 스캐너, 카메라, 외부 POS/엑셀 연동 (`EXC-04`)
- SMS, 카카오 알림톡, 이메일, 모바일 푸시 등 외부 알림 (`EXC-05`)
- 사용자 로그인, 계정/권한 분리, 다중 사용자 및 동시 write 처리 (`EXC-06`)
- 웹/모바일 UI, 클라우드 저장소, 다중 기기 동기화, 배포 파이프라인 (`EXC-07`)
- 결제, 발주/거래처 관리, 매출 통계, 단위 자동 변환 (`EXC-08`)

## 2. 단계별 구현 순서 (Implementation Sequence)

```
[1단계: 도메인 모델 및 유효성 검증]
       │
       ▼
[2단계: 원자적 파일 영속화 계층]
       │
       ▼
[3단계: 핵심 비즈니스 로직 서비스]
       │
       ▼
[4단계: CLI 인터페이스 및 한국어 I/O 포맷터]
       │
       ▼
[5단계: 검증 테스트 및 예외 시나리오 통합 점검]
```

### 단계 1: 도메인 모델 및 유효성 검증 계층
1. TypeScript strict 모드 기반의 Lot 인터페이스 및 값 객체(Value Object) 정의.
2. 안전한 정수 검증기(`Number.isSafeInteger`) 구현: 수량(0 이상), 증감량(정수), N(0 이상).
3. 날짜 유효성 검증기 구현: `YYYY-MM-DD` 정규식 포맷 검증, 윤년/월별 일수 확인(Asia/Seoul 달력 기준), 시스템 시각 미참조.
4. 문자열 검증기 구현: `lotId`, 상품명, 단위의 공백 제거 후 빈 문자열(`trim().length === 0`) 거부.

### 단계 2: 원자적 파일 영속화 계층 (Storage Engine)
1. 데이터 저장소 경로 지정 및 단일 UTF-8 JSON 입출력 모듈 작성.
2. 읽기 단계: 파일 부재 시 빈 저장소 반환, 파일 파싱 오류/손상 시 예외 발생 및 원본 보존.
3. 쓰기 단계: `[대상파일].tmp` 생성 -> JSON 직렬화 및 쓰기 -> `fs.rename`을 통한 원자적 교체.
4. 예외 처리: 쓰기/교체 실패 시 원본 파일을 절대 초기화하거나 빈 파일로 덮어쓰지 않고 에러 throw.

### 단계 3: 비즈니스 로직 계층 (Inventory Service)
1. `addLot`: 중복 `lotId` 검증 -> 신규 lot 추가 -> 파일 원자적 저장.
2. `updateQuantity`: `lotId` 존재 여부 확인 -> `기존 수량 + 증감량` 계산 -> 0 이상 및 안전 정수 범위 확인 -> 파일 원자적 저장.
3. `listAll`: 전체 lot 반환 (수량 0 포함).
4. `listExpiring`: 기준일 + N 계산(날짜 범위 오버플로 방지) -> 수량 > 0 필터링 -> 만료/임박 분류 -> 복합 정렬(유통기한 오름차순, 동일 시 lotId 오름차순).

### 단계 4: CLI 인터페이스 및 한국어 입출력 핸들러
1. CLI 인자 파서 구현 (등록, 증감, 전체 조회, 만료/임박 조회 서브커맨드 매핑).
2. 조회 결과 테이블 및 포맷된 한국어 출력기 구현.
3. 모든 예외 상황에 대한 사용자 친화적 한국어 오류 메시지 표준화.

### 단계 5: 통합 검증 및 시나리오 테스트
1. REQ-01 ~ REQ-05 전 항목 단위/통합 테스트 작성.
2. 비정상 입력(손상된 JSON, 음수 수량, 유효하지 않은 날짜, 빈 문자열 등) 시 복원력 검증.

## 3. 빠뜨리기 쉬운 규칙 및 경계 조건 (Critical Rules)

1. **수량 0 처리의 비대칭성**:
   - `전체 재고 조회 (REQ-03)`: 수량이 0인 lot을 **반드시 포함**하여 출력.
   - `만료/임박 조회 (REQ-04)`: 수량이 0인 lot은 **반드시 제외**.
2. **증감량 0 입력 처리**:
   - 증감량으로 `0`이 입력되었을 때 에러가 아니며, 기존 수량을 그대로 유지하고 성공 응답 처리 (`REQ-02`).
3. **엄격한 안전 정수 범위 검증**:
   - 수량, 증감량, 기준일 더하기 N은 JavaScript의 `Number.isSafeInteger`를 만족해야 함.
   - 소수점(float), `NaN`, `Infinity`, 지수 표기법 등 안전 정수가 아닌 입력은 원천 차단.
4. **날짜 계산 및 타임존 독립성**:
   - Node.js 실행 환경의 OS 로컬 시각(`new Date()`)을 시스템 기준일로 자동 사용하지 않음.
   - 모든 날짜는 명시된 `YYYY-MM-DD` 문자열을 기반으로 순수 달력 계산(Asia/Seoul 기준 날짜 범위)을 수행.
   - 존재하지 않는 날짜(예: `2026-02-29` 평년, `2026-04-31`) 엄격히 거부.
   - `기준일 + N` 계산 결과가 표현 가능한 날짜 범위를 초과할 경우 안전하게 오류 처리.
5. **원자적 파일 교체 및 무결성 보존**:
   - 쓰기 실패가 발생하더라도 기존 데이터 파일(`inventory.json`)의 내용을 임의로 초기화하거나 손상 상태로 남겨두지 않음.
   - JSON 파싱 오류 발견 시 새로운 빈 파일로 덮어쓰지 않고, 읽기 실패 오류를 명확히 보고.

## 4. 위험 요소 및 대응 방안 (Risks & Mitigations)

| 위험 요소 | 영향 | 대응 방안 |
| :--- | :--- | :--- |
| **파일 쓰기 도중 비정상 종료 (전원 꺼짐, 프로세스 kill)** | JSON 파일 손상 및 재고 데이터 유실 | 데이터를 임시 파일(`.tmp`)에 완전히 플러시한 후 OS 수준의 `rename`을 호출하여 원자적(Atomic) 교체 수행 |
| **정수 오버플로 및 정밀도 손실** | 재고 수량 계산 왜곡 발생 | 모든 수량 및 N 입력/연산 결과에 대해 `Number.isSafeInteger` 검증을 강제하고 범위를 벗어날 경우 연산 중단 |
| **런타임 타임존 불일치로 인한 날짜 왜곡** | 만료일 판단 착오 및 임박일 계산 오류 | `Date` 객체의 로컬 타임존 변환을 배제하고, 순수 문자열 분해 및 정수 기반 달력 연산(연/월/일) 적용 |
| **손상된 JSON 파일 존재 시 자동 초기화 위험** | 기존 데이터 덮어쓰기로 인한 데이터 복구 불가 | 로드 실패 시 자동 복구(빈 파일 생성)를 금지하고, 백업 및 확인을 요구하는 한국어 에러 메시지를 출력하며 즉시 중단 |

## 5. 확인 가능한 완료 조건 (Acceptance Criteria)

### REQ-01: 신규 lot 등록
- [ ] 중복되지 않는 `lotId`, 유효한 상품명, 0 이상의 정수 수량, 유효한 단위, `YYYY-MM-DD` 형식의 정상 유통기한 입력 시 등록이 성공하고 파일에 영속화된다.
- [ ] 이미 존재하는 `lotId`로 등록 시도시 에러 메시지를 출력하고 저장을 거부한다.
- [ ] `lotId`, 상품명, 단위 중 하나라도 공백 문자로만 구성되었거나 빈 문자열인 경우 등록을 거부한다.
- [ ] 수량이 음수, 소수점, `NaN`, 안전 정수를 초과하는 값인 경우 등록을 거부한다.
- [ ] 유통기한이 존재하지 않는 달력 날짜(예: `2026-02-30`)인 경우 등록을 거부한다.

### REQ-02: lotId별 수량 증감
- [ ] 존재하는 `lotId`에 양수 정수를 입력하면 해당 수량만큼 증가한다.
- [ ] 존재하는 `lotId`에 음수 정수를 입력했을 때 결과가 0 이상이면 정상 차감된다.
- [ ] 차감 결과 수량이 0 미만이 되는 경우, 수량을 변경하지 않고 명확한 오류를 반환한다.
- [ ] 증감량으로 0을 입력하면 오류 없이 기존 수량이 그대로 유지된다.
- [ ] 존재하지 않는 `lotId`를 대상으로 증감을 시도하면 에러를 반환하고 데이터 상태를 유지한다.
- [ ] 증감 연산 결과가 안전 정수 최대값을 초과하는 경우 에러를 반환하고 데이터를 변경하지 않는다.

### REQ-03: 전체 재고 조회
- [ ] 조회 실행 시 등록된 모든 lot의 `lotId`, 상품명, 수량, 단위, 유통기한이 한국어로 명확히 표시된다.
- [ ] 수량이 0인 lot도 전체 목록에서 누락되지 않고 정상 표시된다.

### REQ-04: 유통기한 만료 및 임박 조회
- [ ] 기준일 `2026-05-10`, `N=3` 입력 시:
  - `유통기한 < 2026-05-10`인 lot은 "만료 목록"에 분류된다.
  - `2026-05-10 <= 유통기한 <= 2026-05-13`인 lot은 "임박 목록"에 분류된다.
- [ ] 수량이 0인 lot은 유통기한 조건에 부합하더라도 만료/임박 조회 목록에서 완전히 제외된다.
- [ ] 조회 결과는 유통기한 오름차순으로 정렬되며, 유통기한이 같은 경우 `lotId` 오름차순으로 정렬된다.
- [ ] N에 음수, 소수점, 안전 정수 범위를 초과하는 값이 입력되면 조회를 거부한다.
- [ ] 기준일 포맷이 잘못되었거나 달력상 유효하지 않은 날짜인 경우 조회를 거부한다.

### REQ-05: 영속화 및 무결성
- [ ] 도구를 종료하고 재실행해도 이전에 등록/변경된 데이터가 온전히 조회된다.
- [ ] 저장 파일은 UTF-8 형식의 단일 JSON 파일로 유지된다.
- [ ] 저장 도중 오류를 시뮬레이션(권한 없음, 디스크 에러 등)했을 때, 기존 데이터 파일이 0바이트가 되거나 손상되지 않고 보존된다.
- [ ] JSON 파일이 손상된 상태(구문 오류 등)에서 프로그램을 실행할 경우, 파일을 빈 상태로 초기화하지 않고 오류 원인을 한국어로 출력하며 안전하게 종료한다.

## 6. 미확정/추후 결정 사항 (Explicit Unknown Decisions)

- **CLI 서브커맨드/플래그 명칭 체계**:
  - 커맨드라인 인터페이스의 서브커맨드 형태(`lot register`, `lot update` 등) 또는 옵션 플래그 형태(`--add`, `--increase` 등)의 구체적인 CLI 문법 규격은 상세 작업 지시서 작성 시 확정한다.
- **기본 데이터 파일 저장 경로**:
  - 실행 위치 기준 상대 경로(`data/inventory.json`) 또는 사용자 홈 디렉터리 경로 여부는 단일 사용자 로컬 환경 기준에 맞춰 작업 지시 단계에서 기본값을 명시한다.
