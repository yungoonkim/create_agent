# 기획안 v1 인수 점검

- 대상: `supervisor-gemini-acceptance-plan v1`, 승인된 `scope-v4 v4` 기준.
- Gemini Writer가 한국어 기획을 생성했고 Gemini Reviewer는 review-1 / pass / issues 0을 반환했다. 실제 제품 검사를 실행한 결과는 아니다.
- 상태: 최종 사용자 승인 pending. [실제 기획안 원문](primary-plan-v1.md), [기획 JSON](primary-plan-v1.json), [실제 Reviewer 결과](primary-review-v1.json).

## 시험 진행자 내용 대조

| 항목 | 기획안 근거 | 내용 판정 |
| --- | --- | --- |
| lot 식별·서로 다른 날짜 보존 | REQ-01, 단계 1 및 addLot | lotId·상품명·수량·단위·날짜를 각각 유지하는 설계 포함 |
| 정수·증감·0·오버플로 | REQ-02, 단계 1/3, 완료 조건 | 음수 증감량 허용, 음수 결과 거부, 0 변경 성공과 안전 정수 검증 포함 |
| 만료·임박 경계 | REQ-04, 규칙 1/4, 완료 조건 | 만료는 기준일 미만, 임박은 양 끝 포함, 수량 0 제외 |
| 기준일·정렬 | REQ-04, 단계 3 | PC 현재 시각 미참조, 날짜/lotId 복합 정렬 포함 |
| 입력·손상·저장 실패 | REQ-01/05, 단계 1/2, 위험·완료 조건 | 달력 검증, 중복·빈 문자열 거부, 손상 파일 자동 초기화 금지, 임시 파일 후 교체 포함 |
| 요구 추적·순서·제외 | 1장·2장·5장 | REQ-01~05 및 EXC-01~08, 계층 순서, 요구별 완료 조건 포함 |

문서의 규칙을 시험표(기준일 2026-11-08, N=2)에 적용하면 LOT-A 만료, LOT-B·C 임박, LOT-D 범위 밖, LOT-E 수량 0 제외를 설명할 수 있다. LOT-B 수량 5에 -2를 적용하면 3, 이어 -4는 거부하고 3을 유지한다. **이는 기획 내용 대조이며 제품 코드 실행 통과 판정이 아니다.**

## 상세 작업 지시에서 확인할 항목

- Reviewer 제안대로 CLI 서브커맨드/플래그와 기본 데이터 경로를 명세해야 한다. 기획안은 이 두 항목을 작업 지시 단계의 미확정 사항으로 남겼다.
- '지수 표기법 등 안전 정수가 아닌 입력' 문구는 입력 문자열 문법과 숫자 값의 안전 정수 여부를 구분할 필요가 있다. 예컨대 숫자 값 1000 자체는 안전 정수다. 작업 지시에서 CLI 숫자 표기 허용 문법을 명시하고 Number.isSafeInteger만으로 표기법까지 검증한다고 설명하지 않아야 한다.
- 로드한 JSON은 문법 오류뿐 아니라 lot 필드·수량·날짜·중복 ID도 검증하도록 저장 계층 지시를 구체화해야 한다. 단순 JSON.parse 성공만으로 유효한 재고 데이터라고 판정하면 안 된다.
- 원자적 rename은 모든 전원 장애의 영구 보존을 자동 보장하지 않는다. '완전히 플러시'의 구체 동작과 오류 검증 범위를 지시서에 명시하고, 수행하지 않은 전원 장애 검증을 완료로 주장하지 않아야 한다.

핵심 규칙은 포함됐으나 위 세부사항은 아직 작업 지시로 검증하지 않았다. 원본 기획이나 Reviewer 결과를 수정하지 않고 점검 메모로 분리했다. 사용자는 기획안 v1을 승인하거나 수정을 요청할 수 있다.

검토용 Markdown 사본은 줄 끝 공백만 제거했다. JSON 스냅샷과 런타임 기획 원문은 변경하지 않았다.
