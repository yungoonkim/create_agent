# 프로젝트 기획 및 작업 지시서: 로컬 로트(Lot) 재고·유통기한 관리 CLI 도구

본 문서는 점주 1인이 로컬 환경에서 로트(lot) 단위 재고 및 유통기한을 안전하게 기록하고 조회할 수 있는 Node.js CLI 도구의 상세 기획 및 작업 지시안(v3)입니다. 본 문서는 검토용 초안이며 승인 또는 실행 상태를 나타내지 않습니다.

---

## 2. 프로젝트 목표 및 제약사항

* **목표**: Node.js CLI 환경에서 입력값 검증, 로컬 UTF-8 JSON 원자적 영속화, 명시된 기준일과 가변/기본 $N$일 기반 만료·임박 조회를 제공하는 점주 1인용 재고 관리 도구의 상세 설계 수립.
* **기술 제약**:
  * 런타임: Node.js, 언어: TypeScript (strict 모드).
  * 저장소: 로컬 단일 UTF-8 JSON 파일 (단일 프로세스 순차 실행 환경).
  * 수치 제약: 모든 수량 및 $N$은 JavaScript 안전 정수(`Number.isSafeInteger`) 범위 내의 0 이상의 정수. 소수, NaN, 무한대, 음수 재고 불허.
  * 날짜 기준: PC 시스템 시각에 의존하지 않고 명시된 `YYYY-MM-DD`(Asia/Seoul 달력 기준) 기반 검증 및 산술 연산.
  * 언어: 모든 기획 문서, 작업 지시서 및 CLI 인터페이스/오류 메시지는 한국어로 작성.
  * 실행 범위 제한: 본 세션은 기획 및 작업 지시서 작성 단계이며, 실제 제품 코드 구현 및 팀원 Agent 실행은 수행하지 않음.

## 3. 구현 순서 (Implementation Phases)

### 1단계: 도메인 타입 및 검증 모듈 (Core Types & Validation)
1. **도메인 모델 정의**:
   * `Lot` 인터페이스: `lotId` (string), `productName` (string), `quantity` (number), `unit` (string), `expirationDate` (string).
   * CLI 커맨드별 입력 DTO 정의.
2. **입력값 검증기**:
   * 문자열: 트림 후 비어있지 않음(`val.trim().length > 0`) 검증.
   * 정수 표기: 정규식(`^-?\\d+$`, 양수/0 한정 시 `^\\d+$`)으로 1차 검사 후 `Number.isSafeInteger()` 충족 여부 확인.
3. **달력 날짜 처리 모듈**:
   * `YYYY-MM-DD` 형식 및 Asia/Seoul 달력 유효일 검증 (윤년 2월 29일, 월별 30/31일 제한 엄격 적용).
   * 시스템 시각 미참조 순수 문자열/달력 일수 가감 계산.
   * $N$일 가산 시 월말/연말 자리올림 및 지원 날짜 범위 초과 검증.

### 2단계: 안전한 원자적 영속화 계층 (Storage Engine)
1. **JSON 파일 로드 및 전수 무결성 검증**:
   * 파일 부재 시: 빈 컬렉션(`[]`) 초기화.
   * 파일 존재 시: UTF-8 읽기 $\to$ JSON 파싱 $\to$ 최상위 배열 확인 $\to$ 각 필드 타입/규격 검증 $\to$ **컬렉션 전체 `lotId` 고유성 검증**.
   * 파싱 실패, 스키마 불일치, `lotId` 중복 등 결함 발견 시 명확한 한국어 오류 출력 후 프로세스 중단 (원본 파일 초기화/덮어쓰기 금지).
2. **원자적 저장 메커니즘**:
   * 대상 파일과 동일 디렉터리 내 고유 임시 파일(`.[filename].tmp.[pid].[timestamp]`) 생성.
   * 직렬화 데이터 쓰기 및 디스크 플러시(`fsync`).
   * `fs.promises.rename`으로 원자적 교체 완료.
   * 실패 시 임시 파일 정리(`unlink`) 및 원본 보존. 앱 기동 또는 저장 시 오래된 고아 임시 파일 정리.

### 3단계: 도메인 서비스 로직 (Domain Services)
1. **신규 Lot 등록 (REQ-01)**: `lotId` 중복 확인, 0 이상의 안전 정수 수량 및 유효 날짜 검증 후 추가.
2. **수량 증감 갱신 (REQ-02)**: 대상 `lotId` 확인, `0 <= 기존 수량 + 증감량 <= Number.MAX_SAFE_INTEGER` 검증 후 갱신 (증감량 0 입력 시 수량 유지).
3. **전체 재고 조회 (REQ-03)**: 등록된 전체 Lot 목록 반환 (수량이 0인 Lot 포함).
4. **유통기한 만료 및 임박 조회 (REQ-04)**:
   * 수량이 0인 Lot 제외.
   * $N$ 파라미터 파싱: 미입력 시 `7` 적용, 입력 시 0 이상의 안전한 정수 검증.
   * `유통기한 < 기준일`: **만료** 목록.
   * `기준일 <= 유통기한 <= 기준일 + N일`: **임박** 목록.
   * 정렬: 유통기한 오름차순 $\to$ 동일 날짜는 `lotId` 오름차순.

### 4단계: CLI 커맨드 및 한국어 인터페이스 (CLI Layer)
1. CLI 인자 파서 구현 (필수/선택 옵션 분기).
2. 사용자 친화적 한국어 테이블 출력 포맷 및 예외 상황별 오류 안내 메시지 구현.

## 4. 세부 기능 규칙 및 빠뜨리기 쉬운 예외 처리

* **파라미터 $N$의 기본값 처리 규칙**:
  * 조회 명령 호출 시 $N$ 인자가 누락된 경우 기본값 `7`을 자동으로 부여하여 기준일 포함 8일간(`기준일` ~ `기준일 + 7일`)을 임박 구간으로 계산.
  * $N$이 명시된 경우 빈 문자열이나 부동소수점(`7.0`), 음수 등을 거부하고 정확한 정수 표기만 허용.
* **수량 및 증감 연산 불변식**:
  * 등록 수량: $0 \le \text{수량} \le \text{MAX\_SAFE\_INTEGER}$.
  * 증감량: 양수, 음수, 0 허용. 단, 결과 수량이 0 미만이거나 안전 정수를 초과하는 경우 갱신 거절 및 기존 수량 유지.
* **조회 시 수량 0 로트 취급 차이**:
  * 전체 재고 조회: 수량이 0인 로트도 내역 보존을 위해 목록에 반드시 표시.
  * 만료/임박 조회: 수량이 0인 로트는 재고가 없으므로 계산 대상에서 완전히 제외.
* **날짜 경계 및 산술 규칙**:
  * 기준일 당일(`유통기한 == 기준일`)은 만료가 아니며 임박 구간에 포함.
  * $N=0$인 경우, 임박 구간은 `유통기한 == 기준일`인 항목만 해당.
  * 기준일 또는 $N$ 계산 결과가 유효 달력 범위를 벗어날 경우 연산 거부.

## 7. 인수 조건 및 검증 기준 (Observable & Testable Acceptance Criteria)

### REQ-01: 신규 Lot 등록
* [ ] 이미 저장된 `lotId`와 동일한 식별자로 등록 시도 시 오류 메시지를 출력하고 등록을 거부한다.
* [ ] `lotId`, `productName`, `unit`에 빈 문자열 또는 공백만 입력된 경우 등록을 거부한다.
* [ ] 등록 수량에 음수, 소수점, 지수 표기, 안전 정수를 초과하는 값이 입력되면 등록을 거부한다.
* [ ] 유통기한에 `2025-02-29`, `2024-13-01` 등 존재하지 않는 달력 날짜가 입력되면 등록을 거부한다.

### REQ-02: 수량 갱신
* [ ] 등록되지 않은 `lotId`에 대해 수량 변경 시도 시 오류를 반환하고 데이터를 변경하지 않는다.
* [ ] 변경 결과 수량이 0 미만이 되는 음수 증감량 입력 시 오류를 반환하고 기존 수량을 유지한다.
* [ ] 증감량으로 0 입력 시 오류 없이 성공하며 기존 수량이 유지된다.
* [ ] 변경 결과가 `Number.MAX_SAFE_INTEGER`를 초과할 경우 연산을 거부한다.

### REQ-03: 전체 재고 조회
* [ ] 수량이 0인 로트를 포함하여 저장된 모든 로트의 `lotId`, 상품명, 수량, 단위, 유통기한이 정상 출력된다.

### REQ-04: 유통기한 만료 및 임박 조회
* [ ] 수량이 0인 로트는 유통기한 도래 여부와 관계없이 만료 및 임박 목록에서 모두 제외된다.
* [ ] 조회 시 $N$을 지정하지 않은 경우 기본값 7일이 적용되어 `기준일 <= 유통기한 <= 기준일 + 7일` 구간이 임박 목록으로 출력된다.
* [ ] 조회 시 $N$을 0 이상의 정수로 명시한 경우 해당 값이 적용되어 `기준일 <= 유통기한 <= 기준일 + N일` 구간이 임박 목록으로 출력된다.
* [ ] 유통기한이 기준일보다 이전인 로트는 만료 목록으로 분류된다.
* [ ] 만료 및 임박 목록은 각각 유통기한 오름차순, 동일 유통기한 내에서는 `lotId` 오름차순으로 정렬된다.
* [ ] $N$에 음수, 소수점 또는 지원 범위를 벗어난 날짜 연산을 유발하는 값이 입력되면 조회를 거부한다.

### REQ-05: 영속화 및 무결성 보장
* [ ] CLI 재실행 후에도 이전 등록 및 수량 갱신 데이터가 유실 없이 로드된다.
* [ ] 저장 작업 시 임시 파일 생성 후 원자적 교체(`rename`)가 이루어지며, 디스크 쓰기 오류 시 기존 원본 파일이 손상되지 않는다.
* [ ] JSON 파일 내에 필수 필드 누락, 형식 불일치, 또는 중복된 `lotId`가 포함된 경우 구체적 오류를 보고하고 기존 파일을 초기화하거나 덮어쓰지 않는다.
