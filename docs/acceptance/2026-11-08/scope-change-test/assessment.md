# 격리 Scope 변경 승인·거절 결과 점검

[두 분기 결과](results.json). 사용자는 Scope v5 원문을 검토하고 별도 복사본의 승인·거절 시험 진행을 허용했다. 실제 primary Scope v4/기획 v3은 변경하지 않았다.

| 항목 | 거절 분기 | 승인 분기 |
| --- | --- | --- |
| Scope 변경/새 Scope 결정 | 각각 rejected | 각각 approved (격리 시험용) |
| 현재 Scope | 기존 v4 유지 | 시험 v5 |
| 현재 기획 | 기존 독립 재현 v2 유지 | 새 v3 작성·review-3 pass |
| 총 기획 반복 | 2/5 유지, 모델 미호출 | 3/5, 예산 유지 |
| 이전 Scope/Plan/Review | 동일 스냅샷 보존 | 동일 스냅샷 보존 |
| 새 기획 최종 승인/작업/팀원 | 기록·실행하지 않음 | 최종 승인 pending, 작업·팀원 없음 |

승인 분기 기획은 N 생략 시 7일 적용, 명시한 N 우선 및 기존 안전 정수 검증, N=0, 명시 기준일과 양 끝 포함 경계를 개정 요약·규칙·완료 조건에 명시했다. 기준일~기준일+7일은 양 끝 포함 8개 날짜임을 설명했다. 이 기획은 비교 시험의 결과이며 primary 승인 기획을 대체하지 않는다.

거절 분기는 기본값 변경을 채택하지 않고 기존 Scope·기획 상태를 보존했다. user-requested 변경 거절은 새 모델 호출을 강제하지 않고 원래 기획 승인 절차로 돌아가는 설계대로 동작했다. Reviewer가 요구한 Scope 변경을 거절하고 재개하는 별도 경우는 기존 fixture 회귀 검증 근거를 따른다.

[승인 분기 기획](approve/plan-v3.md), [검토 원문](approve/reviews-v3.json), [승인 결정 두 레코드](approve/decisions.json), [거절 결정 두 레코드](reject/decisions.json)를 보존했다. 두 분기의 복사본은 서로 분리하며 실제 primary 메모리로 합치지 않는다.
