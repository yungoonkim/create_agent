# 장보기 목록 관리 도구 기획 사양서

## 제품 목표

브라우저 로컬 환경에서 외부 서버나 로그인 없이 1인 사용자가 장보기 항목(이름, 수량, 메모)을 등록, 수정, 삭제하고 살 것과 산 것 상태를 안정적으로 관리하는 경량 웹 도구다. 비정상 데이터 오염을 차단하고 항목 등록 순서와 단건 조작의 일관성을 영속적으로 보장한다.

---

## 사용자 여정 및 사용 흐름

### 여정 1: 신규 물품 등록과 중복 항목 관리
1. 사용자가 입력창에 물건 이름 `우유`, 수량 `2`, 메모 `저지방`을 입력하고 [추가] 버튼을 누른다.
2. '살 것' 목록에 해당 항목이 즉시 표시된다.
3. 사용자가 다시 물건 이름 `우유`, 수량 `1`, 메모 없이 [추가] 버튼을 누른다.
4. 이름이 같아도 별도의 고유 ID를 부여받은 두 번째 `우유` 항목이 '살 것' 목록 하단에 순서대로 독립 추가된다 (근거: Q-2).

### 여정 2: 구매 완료 및 구매 취소
1. 사용자가 '살 것' 목록에서 첫 번째 `우유 (2개)`의 체크박스를 누른다.
2. 선택한 항목 한 건만 '산 것' 목록으로 이동한다.
3. '산 것' 목록에서 해당 항목의 체크를 해제하면 다시 '살 것' 목록으로 돌아오며, 최초 등록 순번에 해당하는 위치로 복귀한다 (근거: Q-3).

### 여정 3: 항목 수정 및 단건 삭제
1. 사용자가 두 번째 `우유 (1개)`의 [수정] 버튼을 눌러 수량을 `3`으로 변경하고 저장한다. 항목의 고유 ID와 최초 등록 순번은 유지된다.
2. 불필요해진 항목의 [삭제] 버튼을 누르면 확인 대화창이 열린다.
3. 확인 대화창에서 [취소]를 누르면 저장소와 화면에 아무 변화가 없다. [확인]을 누르면 해당 한 건만 영구 삭제된다.

### 여정 4: 재접속 및 데이터 보호
1. 브라우저 창을 닫고 동일 프로필로 다시 접속(`http://localhost:4173`)해도 이전에 등록한 목록과 상태가 그대로 유지된다.
2. 기존 로컬 저장소 값이 깨져 있거나 스키마 규칙을 벗어난 경우, 도구는 기존 데이터를 덮어쓰거나 자동 초기화하지 않고 읽기 전용 경고 상태를 표시하며 모든 쓰기를 차단한다.

## 요구사항별 상세 사양

### R-1: 신규 항목 등록
* **정상 동작**: 물건 이름, 수량, 메모(선택)를 입력하여 목록에 추가한다.
  * 물건 이름: 앞뒤 공백을 제거(trim)한 후 1자 이상이어야 한다.
  * 수량: 1 이상 99 이하의 정수만 허용한다 (근거: Q-1). 가격 및 합계 금액은 취급하지 않는다.
  * 메모: 선택 입력 항목이며, 미입력 시 빈 문자열(`""`)로 저장된다.
* **유효성 검증 및 실패/무변경 동작**:
  * 이름이 공백뿐이거나 비어 있는 경우 등록하지 않고 입력 필드 하단에 오류 메시지를 노출한다.
  * 수량이 1 미만, 99 초과, 소수점 포함, 숫자가 아닌 문자일 경우 등록을 차단하고 입력을 유지한다.
  * 유효성 실패 시 기존 저장 데이터나 목록에는 아무런 변경을 가하지 않는다.
* **중복 처리**: 동일한 물건 이름이 이미 존재하더라도 시스템 내부적으로 서로 다른 고유 ID를 발급하여 독립된 개체로 처리한다 (근거: Q-2).

### R-2: 구역 분리 및 순서 표시
* **구역 분리**: 화면을 '살 것(To Buy)' 구역과 '산 것(Bought)' 구역으로 명확히 구분한다.
* **정렬 불변식**:
  * 각 구역에 표시되는 항목들은 시스템에 최초 등록된 순서(단조 증가 순번 `seq`)를 기준으로 오름차순 정렬된다.
  * 사용자 임의 드래그 앤 드롭 정렬이나 역순 정렬은 제공하지 않는다.
* **식별성**: 동일한 이름을 가진 항목이 복수 개 존재해도 각각 독립된 카드/행으로 렌더링되며 고유 ID로 내부 식별된다.

### R-3: 구매 / 구매 취소 상태 전환
* **정상 동작**: 항목에 연결된 상태 토글 요소(체크박스 또는 버튼)를 클릭하면 해당 단건의 상태가 `살 것(false)` ↔ `산 것(true)`으로 전환된다.
* **순서 보존 규칙**:
  * 상태가 변경되어 다른 구역으로 이동해도 항목의 최초 등록 순번(`seq`)은 불변이다.
  * '산 것'에서 구매 취소하여 '살 것'으로 복귀할 때, 나중에 등록된 항목보다 앞선 순번이었다면 원래의 상대적 순서 위치를 정확히 유지한다 (근거: Q-3).
* **단건 격리**: 동일한 이름의 다른 항목이 존재해도 사용자가 클릭한 정확히 1건만 상태가 전환된다 (근거: Q-2).

### R-4: 항목 정보 수정
* **정상 동작**: 선택한 단일 항목의 이름, 수량, 메모를 폼 또는 모달 창을 통해 수정한다.
* **입력 검증**: R-1과 동일한 검증 규칙(앞뒤 공백 제외 필수 이름, 1~99 정수 수량)을 적용한다.
* **불변식**: 항목의 고유 ID(`id`), 최초 등록 순번(`seq`), 완료 여부(`isBought`)는 수정 시에도 변경되지 않는다.
* **실패 동작**: 검증 실패 시 수정을 반영하지 않고 오류를 표시하며, 기존 항목 데이터를 보존한다.

### R-5: 확인 후 단건 삭제
* **정상 동작**: 삭제 버튼 클릭 시 브라우저 기본 확인 창(`window.confirm`) 또는 자체 모달 창으로 사용자에게 삭제 여부를 재확인한다.
* **확인 시**: 선택한 단일 항목 1건만 영속 저장소와 화면에서 제거된다. 동일 이름의 타 항목에 영향을 주지 않는다.
* **취소 시**: 어떠한 삭제 작업도 수행하지 않으며, 메모리와 로컬 저장소 상태를 그대로 유지한다.

### R-6: 데이터 영속성 및 동시성 제어
* **정상 재접속**: 동일 출처(`http://localhost:4173`) 및 브라우저 프로필 환경에서 페이지를 새로고침하거나 창을 다시 열었을 때 직전 커밋된 전체 목록과 순서가 그대로 유지된다.
* **무결성 보호**: 로컬 저장소의 데이터가 없거나 유효한 경우에만 정상 동작한다. 데이터 손상 발견 시 원본 데이터를 보존하고 쓰기 작업을 전면 차단한다.
* **다중 탭 제어**: 단일 프로필 내에서 배타적 잠금을 소유한 1개 탭만 변경을 수행할 수 있으며, 비소유 탭은 변경이 차단된다.

## 제외 대상 기능 (Out of Scope)

* **X-1 제외 기능**: 사용자 계정/로그인, 외부 원격 서버 동기화, 사용자 간 목록 공유, 온라인 결제/가격 계산, 푸시/마감 알림, AI 기반 구매 목록 자동 추천 기능은 일체 포함하지 않는다.
* **X-2 프로세스 제외**: 실제 소스 코드 구현물 제출, 팀원 실행 테스트, 최종 사용자의 공식 승인 행위는 본 기획 범위에 포함되지 않는다.

## 기술 설계 및 저장소 무결성

### 1. 영속성 스키마 정의
브라우저 `localStorage`의 단일 키(`shopping_list_data`) 아래 JSON 문자열 형태로 전체 애플리케이션 상태를 관리한다.

```json
{
  "schemaVersion": 1,
  "nextSeq": 3,
  "items": [
    {
      "id": "item-20261109-001",
      "seq": 1,
      "name": "우유",
      "quantity": 2,
      "memo": "저지방",
      "isBought": false,
      "createdAt": 1762646400000
    },
    {
      "id": "item-20261109-002",
      "seq": 2,
      "name": "우유",
      "quantity": 1,
      "memo": "",
      "isBought": true,
      "createdAt": 1762646410000
    }
  ]
}
```

* **필드 제약 조건**:
  * `schemaVersion`: 정수 `1` (고정).
  * `nextSeq`: 1 이상의 양의 정수. 새 항목 추가 시마다 1씩 단조 증가.
  * `items`: 배열. 각 항목의 `id`는 고유 문자열, `seq`는 `nextSeq`보다 작은 고유 양의 정수.
  * `name`: 공백 제거 후 1자 이상의 문자열.
  * `quantity`: 1 이상 99 이하의 정수.
  * `memo`: 문자열 타입.
  * `isBought`: 불리언 타입 (`true` / `false`).
  * `createdAt`: 밀리초 타임스탬프 (정수). 단, 정렬 기준은 시스템 클럭에 의존하지 않고 단조 증가하는 `seq` 값을 사용한다.

### 2. 저장소 상태 판별 및 복구/보존 정책
애플리케이션 구동 시 로컬 저장소 값을 읽어 엄격히 검증한다.

* **최초 실행 (Normal Init)**:
  * 저장소 키의 조회 결과가 정확히 `null`인 경우에만 정상 최초 실행으로 간주한다.
  * 초기 메모리 상태(`schemaVersion: 1, nextSeq: 1, items: []`)를 생성하되, 사용자가 첫 등록을 성공하기 전까지는 저장소에 불필요한 빈 쓰기를 수행하지 않는다.
* **손상 및 위반 데이터 처리 (Corrupt / Invalid State)**:
  * 다음의 경우는 모두 비정상 데이터로 분류한다:
    * 키가 존재하나 빈 문자열(`""`) 또는 공백 문자열인 경우
    * JSON 파싱 오류(`SyntaxError`)가 발생하는 경우
    * `schemaVersion`이 1이 아니거나 지원되지 않는 버전인 경우
    * 필수 키 누락, 타입 불일치, `quantity` 범위 초과(1~99 외)
    * `items` 내 `id` 또는 `seq` 중복, `seq >= nextSeq`인 불변식 위반
  * **보존 정책**: 기존 저장소 값을 절대 빈 값으로 덮어쓰거나, 파싱 가능한 일부만 잘라내어 저장하거나, 자동 리셋(`localStorage.clear()`)하지 않는다. 원본 텍스트를 그대로 유지한다.
  * **화면 및 동작**: 화면에 "저장 데이터 손상 또는 지원되지 않는 버전입니다. 원본 보존을 위해 수정이 제한됩니다." 경고를 표시하고, 모든 입력 폼과 변경 버튼을 비활성화(Read-Only Lock)한다.

### 3. 쓰기 커밋 경계 및 트랜잭션 흐름
모든 상태 변경(등록, 수정, 토글, 삭제)은 엄격한 3단계 파이프라인을 따른다.

1. **후보 검증 및 직렬화**: 메모리 변경 후보 객체를 생성하고 스키마 불변식을 사전 검증한 뒤 JSON 문자열로 직렬화한다.
2. **저장소 커밋 (`localStorage.setItem`)**:
   * 브라우저 저장소 쓰기를 먼저 수행한다.
   * `QuotaExceededError` 등 저장 실패 시: 로컬 저장소의 기존 값을 보존하고, 인메모리 상태와 사용자 입력 폼의 입력값을 그대로 유지한 채 사용자에게 "저장 공간 부족으로 저장에 실패했습니다"라는 오류를 고지한다.
3. **메모리 및 화면 반영**:
   * 저장소 쓰기가 정상 완료된 후에만 실제 애플리케이션 상태를 확정하고 UI를 갱신한다.
   * 저장소 쓰기 성공 후 UI 렌더링 중 예기치 못한 스크립트 오류가 발생한 경우: "저장은 완료되었으나 화면 갱신에 실패했습니다. 페이지를 새로고침해 주세요."를 안내하며, 임의로 저장을 롤백했다고 안내하지 않는다.
   * (참고: 단말기 급작 전원 차단 등 OS/하드웨어 수준의 비정상 종료까지 완벽히 방어하지는 않는다.)

### 4. 탭 동시성 제어 (Web Locks API)
동일 브라우저 프로필에서 여러 탭이 동시에 실행될 때 발생할 수 있는 경쟁 상태(Race Condition)를 방지한다.

* **배타 락 획득**:
  * 탭 활성화 시 Web Locks API (`navigator.locks.request('shopping_list_lock', ...)`)를 통해 배타적 잠금을 요청한다.
  * 잠금을 획득한 탭만 "활성 편집 탭"이 되며, 잠금 획득 직후 로컬 저장소에서 최신 데이터를 읽어 화면을 초기화한다.
* **비활성 탭 및 미지원 환경**:
  * 이미 다른 탭이 잠금을 보유하고 있어 획득하지 못한 탭은 즉시 편집 UI를 비활성화하고 "다른 탭에서 작업 중입니다. 해당 탭을 닫거나 작업을 마친 후 새로고침하세요." 메시지를 표시한다.
  * Web Locks API 미지원 브라우저 환경에서는 데이터 오염 방지를 위해 쓰기 기능을 전면 차단하고 읽기 전용으로 동작한다.
* **동기화 원칙**:
  * 백그라운드 탭 자동 병합(Auto-Merge)은 지원하지 않는다.
  * 사용자가 잠금을 쥐고 있던 탭을 닫으면 대기 중이던 탭이 잠금을 획득할 수 있으며, 새로고침 시 최신 저장 데이터를 기준으로 안전하게 시작한다.

| **AC-08** | 새로고침 후 데이터 유지 (R-6) | 항목 3건 등록 및 1건 구매 완료 후 브라우저 새로고침(F5) | 살 것 2건, 산 것 1건의 항목 내용과 순서가 새로고침 전과 완벽히 일치 |

## 용어 정의 (Glossary)

* **살 것 (To Buy)**: 구매 전 상태(`isBought === false`)인 항목들이 모여 있는 영역.
* **산 것 (Bought)**: 구매 완료 상태(`isBought === true`)인 항목들이 모여 있는 영역.
* **등록 순번 (`seq`)**: 항목이 처음 등록될 때 부여되는 고유한 단조 증가 정수값. 시계 오차와 무관하게 정렬 순서를 결정하는 기준.
* **배타적 잠금 (Exclusive Lock)**: 동일 출처 브라우저 내에서 오직 하나의 활성 탭만 데이터 변경 권한을 갖도록 제어하는 상태.
