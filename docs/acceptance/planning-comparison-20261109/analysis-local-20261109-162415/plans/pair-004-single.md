# 생활비 지출 메모 도구 기획 사양서

## 제품 목표
외부 서버 통신이나 금융 이체 기능 없이, 단일 브라우저 로컬 환경에서 일별 생활비(날짜·분류·금액·메모)를 기록하고 월별 내역과 합계를 정확하게 검증·조회할 수 있는 독립형 브라우저 도구를 제공한다.

---

## 사용 흐름

### 1. 첫 접속 및 신규 등록
1. 사용자가 브라우저(`http://localhost:4173`)로 접속한다.
2. 저장소에 키가 없는 최초 실행 상태인 경우 빈 목록과 0원 합계 화면이 표시된다.
3. 조회할 연·월(기본값: 당월 `YYYY-MM`)을 확인한다.
4. 날짜(`YYYY-MM-DD`), 분류(`식비`/`교통`/`기타`), 금액(1원~10,000,000원 정수), 메모(선택)를 입력하고 [등록] 버튼을 누른다.
5. 유효성 검증과 영속 저장에 성공하면 해당 월 목록에 추가되고 월 합계가 즉시 갱신된다.

### 2. 월별 내역 조회
1. 상단 월 선택 컨트롤(`YYYY-MM`)에서 원하는 연·월을 변경한다.
2. 선택한 월의 1일 00:00부터 말일 23:59 사이에 속한 기록만 화면에 표시된다.
3. 목록은 날짜 오름차순으로 정렬되며, 같은 날짜 내에서는 최초 등록된 순서로 나열된다.
4. 목록 하단에 해당 월 기록들의 총합계 금액이 원 단위로 표시된다.

### 3. 기록 수정 및 월 이동
1. 수정할 기록의 [수정] 버튼을 누르고 입력 폼에서 항목(날짜, 분류, 금액, 메모)을 변경한다.
2. [저장]을 누르면 고유 식별자(ID)를 유지한 상태로 데이터가 갱신된다.
3. 날짜가 다른 연·월로 변경된 경우, 기존 조회 월 목록에서 해당 항목이 제외되고 합계가 줄어들며, 변경된 대상 월을 조회할 때 해당 항목과 합계가 정상 반영된다.

### 4. 기록 삭제
1. 삭제할 기록의 [삭제] 버튼을 누르면 확인 대화창이 나타난다.
2. [취소]를 누르면 데이터 변경 없이 기존 상태를 유지한다.
3. [확인]을 누르면 단일 기록이 영구 제거되고, 목록 및 월 합계가 재계산된다.

### 5. 데이터 보호 및 동시 탭 제어
1. 데이터 손상(깨진 JSON, 스키마 불일치 등)이 감지되면 기존 데이터를 덮어쓰거나 초기화하지 않고 모든 변경을 차단한 채 안내를 표시한다.
2. 여러 탭에서 동시 접속 시, 배타 잠금을 점유하지 못한 탭은 수정을 차단하여 데이터 경합을 방지한다.

## 요구사항별 상세 사양

### R-1. 지출 기록 입력 및 검증
- **정상 동작**:
  - 필수 입력값: 날짜(`YYYY-MM-DD`), 분류(`식비`, `교통`, `기타` 중 택1), 금액(`1` ~ `10,000,000` 사이의 원 단위 정수).
  - 선택 입력값: 메모(문자열, 미입력 시 빈 문자열 저장).
  - 중복 허용: 날짜, 분류, 금액, 메모가 완전히 동일한 입력이라도 독립된 고유 ID를 부여하여 별도 항목으로 등록한다.
- **검증 규칙**:
  - 날짜: 유효한 그레고리력 달력 날짜여야 함(윤년 2월 29일 등 검증, 과거·오늘·미래 모두 허용).
  - 분류: `식비`, `교통`, `기타` 외의 값은 불허.
  - 금액: 숫자 형태의 정수만 허용하며 `0`, 음수, 소수점 포함 값, `10,000,000` 초과 값은 거부.
  - 저장 용량 한도: 저장된 총 레코드 수가 1,000건인 상태에서 추가 등록 시도 시 거부.
- **실패/무변경 동작**:
  - 유효성 검증 실패 또는 1,000건 초과 시 기존 저장 데이터와 현재 입력창의 입력값을 그대로 보존하고 저장소 변경을 수행하지 않는다.
- **검증 예시**:
  - 입력: `2026-02-29`(평년), `식비`, `10000` -> 검증 실패, 등록 차단, 기존 목록 유지.
  - 입력: `2026-11-09`, `식비`, `0` -> 검증 실패, 등록 차단.
  - 입력: `2026-11-09`, `교통`, `5500.5` -> 검증 실패, 등록 차단.
  - 기존 1,000건 저장 상태에서 신규 등록 시도 -> 한도 초과 오류 안내, 목록 변동 없음.

### R-2. 월별 목록 조회 및 정렬
- **정상 동작**:
  - 선택된 `YYYY-MM`의 1일 00:00:00부터 말일 23:59:59까지의 기록만 추출하여 표시한다.
  - 정렬 순서: 1차 기준은 날짜 오름차순(`YYYY-MM-DD`), 2차 기준(동일 날짜)은 최초 등록 순서(`seq` 오름차순)를 적용한다.
- **실패/무변경 동작**:
  - 조회 대상 월에 데이터가 없으면 빈 목록을 표시하며 오류를 발생시키지 않는다.
- **검증 예시**:
  - `2026-11` 선택 시 `2026-10-31` 및 `2026-12-01` 데이터는 목록에서 제외.
  - 같은 날짜 `2026-11-05`에 등록된 항목 A(등록 순번 12)와 항목 B(등록 순번 15)는 A -> B 순서로 표시.

### R-3. 월별 합계 표시 및 실패 격리
- **정상 동작**:
  - 현재 선택된 월에 표시된 모든 기록의 금액 총합을 계산하여 표시한다.
- **실패/무변경 동작**:
  - 신규 등록, 수정, 삭제 과정에서 유효성 실패나 스토리지 쓰기 실패가 발생하면 화면의 목록과 합계는 직전 정상 상태를 엄격히 유지한다.
- **검증 예시**:
  - `2026-11` 목록에 10,000원, 25,000원이 있을 때 합계는 35,000원 표시.
  - 신규 등록 시 잘못된 금액(-5,000원) 입력 시 합계는 35,000원으로 유지.

### R-4. 기록 수정 및 월 이동
- **정상 동작**:
  - 특정 기록을 선택하여 날짜, 분류, 금액, 메모를 수정할 수 있다.
  - 수정 시 해당 기록의 내부 고유 ID 및 최초 등록 순번(`seq`)은 변경되지 않고 유지된다.
  - 날짜가 다른 월로 변경된 경우(예: `2026-11-05` -> `2026-12-01`):
    - 변경 전 월(`2026-11`) 목록에서 해당 항목이 제거되고 합계가 차감된다.
    - 변경 후 월(`2026-12`) 조회 시 해당 항목이 포함되고 합계가 증가한다.
- **실패/무변경 동작**:
  - 수정 폼에서 유효하지 않은 값 입력 시 수정 저장이 거부되며 기존 데이터는 그대로 유지된다.
- **검증 예시**:
  - `2026-11-05`의 10,000원 기록을 `2026-12-01`로 날짜 수정 완료 시, `2026-11` 합계는 10,000원 감소, `2026-12` 합계는 10,000원 증가 확인.

### R-5. 단일 기록 확인 후 삭제
- **정상 동작**:
  - 삭제 버튼 클릭 시 사용자에게 삭제 확인 절차를 거친다.
  - 확인 승인 시 선택한 단일 기록만 제거되며, 삭제 후 선택 월의 목록과 합계를 즉시 재계산한다.
- **실패/무변경 동작**:
  - 확인 대화창에서 [취소]를 누르면 저장소 및 화면 목록, 합계에 아무런 변경이 발생하지 않는다.
- **검증 예시**:
  - 10,000원 항목 삭제 시도 중 [취소] 클릭 -> 목록에 잔존, 합계 변동 없음.
  - [확인] 클릭 -> 목록에서 즉시 제거, 합계에서 10,000원 차감 반영.

### R-6. 영속성 및 무결성·동시성 제어
- **정상 데이터 로드**:
  - 재접속 시 정상 스키마를 만족하는 기존 JSON 데이터를 복원하여 화면을 구성한다.
- **저장소 무결성 검증 및 예외 처리**:
  - 저장 키의 값이 `null`(키 부재)인 경우에만 정상 최초 실행으로 간주하고 초기 스키마 객체를 생성한다.
  - 기존 값이 빈 문자열(`""`), 공백 문자열, JSON 파싱 불가능 문자열, 지원하지 않는 `schemaVersion`, 스키마 필드 누락/타입 불일치, 1,000건 초과, 고유 키 중복 등 무결성 위배인 경우:
    - 원본 데이터를 절대 초기화하거나 덮어쓰지 않고 보존한다.
    - 화면에 데이터 손상 경고를 표시하고 신규 등록·수정·삭제 등 모든 쓰기 동작을 원천 차단한다.
- **동시 탭 제어**:
  - 단일 브라우저 프로필 및 동일 origin(`http://localhost:4173`) 내에서 배타 잠금을 획득한 단 1개의 탭만 데이터 변경이 가능하다.
  - 잠금을 획득하지 못한 탭은 쓰기 폼이 비활성화되며, 사용 중인 탭 종료 후 새로고침해야 함을 안내한다.
- **검증 예시**:
  - `localStorage`의 저장 키 값이 `""`(빈 문자열)인 상태로 접속 -> 빈 데이터로 자동 초기화하지 않고 원본 유지 및 변경 차단 상태 진입.
  - 탭 A가 잠금을 점유 중인 상태에서 탭 B 접속 -> 탭 B는 읽기 전용 상태로 진입하여 등록/수정/삭제 버튼 비활성화.

## 제외 범위 사양

### X-1. 외부 연동 및 자동화 기능 제외
- 사용자 계정 생성, 로그인, 인증·인가 기능은 제공하지 않는다.
- 외부 서버 동기화, 다중 사용자 데이터 공유 기능은 제공하지 않는다.
- 은행/카드사 연동, 실제 계좌 이체, 결제 기능은 일체 배제한다.
- 지출 알림(푸시 알림) 및 AI/머신러닝 기반 자동 분류·추천 기능은 제공하지 않는다.
- 반환/환불 처리 워크플로우 및 통화 환율 변환 기능은 제공하지 않는다.

### X-2. 실행 및 승인 범위 제외
- 실제 소스코드 파일 생성, 패키지 빌드 및 배포 실행은 본 기획 범위에 포함되지 않는다.
- 팀원 및 실제 사용자에 의한 최종 인수 승인은 본 문서 작성 단계에서 처리하지 않는다.

## 기술 설계

### 1. 데이터 모델 및 스키마
`localStorage`의 고정 키(`EXPENSE_TRACKER_STORE`)에 단일 JSON 문자열로 저장된다.

```json
{
  "schemaVersion": 1,
  "nextSeq": 3,
  "records": [
    {
      "id": "rec_d1a2b3c4",
      "seq": 1,
      "date": "2026-11-01",
      "category": "식비",
      "amount": 12000,
      "memo": "점심 식사"
    },
    {
      "id": "rec_e5f6a7b8",
      "seq": 2,
      "date": "2026-11-01",
      "category": "교통",
      "amount": 1500,
      "memo": ""
    }
  ]
}
```

- **엔티티 무결성 제약**:
  - `schemaVersion`: 정수 `1`만 유효.
  - `nextSeq`: 1 이상의 양의 정수. 새 레코드 생성 시 단조 증가하여 부여.
  - `records`: 배열 형태이며 길이는 `0` 이상 `1000` 이하.
  - `id`: 각 레코드의 유일한 식별자(UUID 또는 나노아이디 형식 문자열). 중복 불가.
  - `seq`: 등록 순서를 보장하는 고유 정수. 중복 불가.
  - `date`: `YYYY-MM-DD` 정규식 일치 및 실제 존재하는 날짜.
  - `category`: `"식비" | "교통" | "기타"` 리터럴 집합에 포함.
  - `amount`: `1 <= amount <= 10000000` 범위의 정수.
  - `memo`: 문자열 타입.

### 2. 저장소 커밋 파이프라인
데이터 쓰기(등록, 수정, 삭제)는 다음 단계에 따라 원자적으로 수행된다:

1. **잠금 확인**: 현재 탭이 배타적 스토리지 잠금을 소유하고 있는지 확인. 미소유 시 중단.
2. **후보 데이터 검증**: 메모리 상에서 변경 대상 레코드와 전체 스키마 불변식(총 레코드 수 <= 1000, 고유 ID/순번 유일성, 필드 타입 등)을 검증.
3. **직렬화**: 변경된 전체 루트 객체를 JSON 문자열로 직렬화.
4. **스토리지 쓰기**: `localStorage.setItem('EXPENSE_TRACKER_STORE', serializedData)` 실행.
5. **확정 반영**:
   - `setItem`이 성공하면 메모리 내 앱 상태를 갱신하고 화면 목록과 합계를 리렌더링한다.
   - `setItem` 도중 예외(`QuotaExceededError` 등) 발생 시: 메모리 상태와 화면을 갱신하지 않고 기존 저장값을 보존하며, 사용자 입력창의 내용을 유지한 채 저장 실패를 안내한다.
   - 만약 저장소 쓰기 성공 후 UI 렌더링 단계에서 치명적 오류가 발생할 경우, 저장이 취소되었다고 안내하지 않고 "저장은 완료되었으나 화면 갱신에 실패했습니다. 새로고침해 주십시오."라는 복구 안내를 표시한다.

### 3. 동시 탭 배타 잠금 설계
- `Web Locks API` (`navigator.locks.request`)를 사용하여 `expense_tracker_tab_lock` 명칭의 배타 잠금을 획득한다.
- 잠금을 획득한 활성 탭만 등록/수정/삭제 폼을 활성화한다.
- 잠금 획득에 실패한 보조 탭은 읽기 전용 상태로 전환되어 화면 조작 컨트롤이 잠긴다. 활성 탭이 닫히거나 잠금을 해제하면 대기 중인 탭이 잠금을 인계받은 후 저장소에서 최신 데이터를 다시 읽어 화면을 초기화한다.

## 결정 사항 분류

### 사용자 확정 결정 (User Settled Decisions)
- **금액 및 날짜 제약 (Q-1)**: 금액은 원 단위 정수만 허용하고 0, 음수, 소수는 거절한다. 날짜는 실제 달력 날짜이며 과거, 오늘, 미래 모두 허용한다.
- **용량 및 업무 제외 범위 (Q-2)**: 최대 1,000건을 저장하며 초과 등록 시도는 기존 데이터와 입력을 유지한 채 거절한다. 반환/환불 및 통화 변환은 업무 범위에서 제외한다.
- **조회 방식 및 항목 독립성 (Q-3)**: 조회 월은 `YYYY-MM`으로 선택하며, 내용이 완전히 동일한 기록이라도 자동 병합하지 않고 독립 항목으로 유지한다.

### 기획 위임 설계안 (Delegated Design Proposals)
- **정렬 순번 필드 (`seq`)**: 동일 날짜 내 최초 등록 순서를 시스템 시계 오류와 무관하게 보장하기 위해 단조 증가 카운터(`nextSeq`)를 저장 스키마에 포함.
- **동시성 잠금 메커니즘**: 표준 브라우저 환경에서 가장 안전한 배타 잠금을 보장하기 위해 `Web Locks API` 적용.
- **단일 스토리지 키 관리**: 무결성 검증 실패 시 파편화 없는 데이터 보존을 위해 단일 JSON 키(`EXPENSE_TRACKER_STORE`) 방식으로 통합 관리.

### 미해결 결정 사항 (Unresolved Decisions)
- 현재 승인된 스코프 및 확정된 제약 조건 내에서 기획 사양 완결되어 추가 미해결 사항 없음.
