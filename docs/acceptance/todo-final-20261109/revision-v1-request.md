승인 Scope v6/Plan v4를 그대로 유지하며 작업 지시 v1의 아래 모호함을 보완하라. 실제 제품 구현·팀원 실행·작업 초기화를 하지 않고 미래 구현을 위한 작업 지시 제안만 작성한다. 사용자에게 재질문할 제품 선택은 없으며 아래 기술 선택은 위임된 구현 구체화다. 요구사항 전체와 기존 정상 기능은 유지하고 의존성과 산출물/완료 조건을 일치시켜라.

1. 환경/검증 선행 작업을 구체화한다. 미래 제품은 별도 standalone 디렉터리의 표준 JavaScript 모듈/HTML/CSS, Vite 정적 개발 서버, Vitest+jsdom 단위/DOM 테스트, Playwright 실제 브라우저 수락 검증으로 제안한다. React나 백엔드 API/로그인/원격 동기화 등 추가 기능은 넣지 않는다. 고정 URL은 http://127.0.0.1:3000, host127.0.0.1/port3000/strictPort로 정하고 포트 점유 시 다른 포트로 자동 전환하지 말고 명확히 실패한다. npm scripts dev/build/test/test:e2e와 각 설정·테스트 준비 파일/README를 선행 작업 산출물로 제안한다. 이 명령들은 미래 제품의 검증 안내이지 이 ADTF 세션에서 실행할 허가가 아니다. 원격 서버/업로드 기능은 없다.
2. 각 작업에 그 작업의 의미 있는 테스트 파일을 산출물로 포함한다. 환경 설정만 있는 첫 단계, 순수 검증/모델, 저장소, UI 컴포넌트, 항목 동작, 최종 통합/브라우저 시나리오 등 이미 제안한 역할과 DAG를 유지해도 된다. 테스트를 마지막 작업에서만 만든다고 하지 않는다.
3. 컴포넌트·행동 처리·최종 app 연결 경계를 명확히 한다. UI 폼/리스트 작업이 아직 없는 최종 app을 요구하는 AC를 갖지 않도록, 해당 단계는 주입한 콜백/가짜 저장소를 사용하는 컴포넌트 검증과 마지막 실제 연결 검증을 구분하라. 후보 생성/검증/직렬화 -> 단일 setItem 성공 -> 확정 상태/UI 갱신 순서의 소유 모듈/계약을 정하고 모든 등록/수정/완료/완료취소/삭제에 동일하게 적용하라. 저장 전 임의 낙관적 화면 반영은 금지한다.
4. 저장소 읽기 접근 예외, 키 부재 null, 빈 문자열(''), JSON null/깨진 JSON, 모르는 버전·필드, 필수 필드·타입·값/ID·순번 중복·카운터관계 오류를 테스트 조건에 명시한다. 로드 시 nextSequence/sequenceNumber 양의 안전 정수, 빈 목록 maxSequence0, title의 공백/문자열, memo문자열(빈 허용), isCompleted 실제boolean, 유효한 필수 dueDateTime, 고유 비공백id를 검증한다. 키 부재만 정상 첫 실행이고 손상/읽기실패는 원본을 덮어쓰지 않으며 모든 변경 동작을 차단한다. 별도 복원 도구를 추가하지 않는다.
5. 고유 ID의 생성/충돌 검사 규칙을 정하고 ID/sequenceNumber는 기존 항목 수정·완료·취소로 바꾸지 않는다. 새 등록 성공 때만 nextSequence를1증가시키며 배정값과 증가 후 값 모두 안전 정수인지 먼저 검사한다. 한도 소진/검증/저장 실패면 저장값·확정 목록·카운터·입력을 보존한다. 시계 역행, 같은 시각, 삭제 후 재등록, 재시작 후 순번 불변을 예제/테스트로 명시한다.
6. 입력은 제목·마감일시 필수/메모 선택, 과거마감 허용, 타임존 없는 YYYY-MM-DDTHH:mm·연도0001~9999·윤년실존날짜·시00~23·분00~59다. HTML 형태 제목/메모는 textContent 등으로 글자로만 표시하며 불필요한 escapeHtml 파일로 이중 이스케이프하지 않는다.
7. 저장 전/쓰기 예외와 commit 이후 화면 실패를 AC에서 각각 검증하라. 전자는 성공 문구 금지·기존 확정 데이터/입력 보존·재시도 가능, 후자는 저장은 되었음을 알리고 새로고침 복원(이미 저장된 내용을 자동 롤백했다고 주장하지 않음)이다. 실제 물리 장애/전원 차단 무손실 보장을 주장하지 않는다.
8. 삭제 확인 취소는 저장 API 호출 없이 무변경이다. 동일 제목 여러 항목 중 선택 ID1건만 수정/완료/취소/삭제됨을 테스트한다. 손상·읽기 실패 또는 외부 storage 변경 감지 시 추가/수정/완료/완료취소/삭제 전부 차단하고 새로고침 재검증을 안내한다. storage 이벤트는 완벽한 다중 탭 충돌 방지/잠금/동시성 보장을 주는 기능이 아니다. 지원은 단일 탭 순차 편집이다.
9. 최종 브라우저 수락은 단순 새로고침과 실제 브라우저 종료/재실행을 구분한다. 동일 임시 persistent profile·동일 고정 origin을 재사용하는 시나리오 또는 이에 상응하는 명시적 수동 절차를 제안해 미완료/완료 목록과 수정·삭제/순번을 확인하게 한다. 비공개 창/사이트데이터 삭제/다른 기기·브라우저/file:// 미보장 한계 안내도 README 산출물에 포함한다. 이 세션에서 제품/제품 테스트를 실행했다고 주장하지 않는다.

결과는 기존 JSON 작업 제안 형식으로, 요구 ID·의존성·파일 경로·검증 방법·판정 가능한 구체적 AC를 담아라. 기존 Scope/Plan 출처·승인·검증 예산은 모델이 바꾸지 못한다. 작업의 filename은 미래 제품 디렉터리 기준이며 ADTF 저장소 자체를 수정하는 지시로 혼동하지 않게 하라.
