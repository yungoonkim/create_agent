# [기획안 초안 v2] 개인용 로컬 웹 할 일 관리 도구

> **안내:** 본 문서는 사용자의 공식 최종 승인을 받기 전 검토를 위한 **미승인 기획안 초안(Plan v2)**입니다. 승인된 범위(Scope v4)에 따라 기획 및 작업 지시 내용을 정의하며, 실제 프로그램 코드 구현이나 에이전트 실행은 이번 세션에서 수행하지 않습니다.

---

## 0. 기획안 변경 요약 (Plan v1 → Plan v2)

* **저장소 데이터 상태 구분 정밀화:** 브라우저 로컬 저장소(`localStorage`)에 키 자체가 없는 상태(Absent), 키는 있으나 빈 문자열/공백인 상태(Present Empty), JSON 형식이 깨졌거나 스키마가 불일치하는 상태(Corrupt/Invalid)를 명확히 구분하여 처리 기준을 보강했습니다.
* **비파괴적 데이터 보존 규칙 확인:** 손상되거나 비정상적인 데이터가 발견될 경우 사용자의 원본 데이터를 자동 삭제하거나 덮어쓰지 않고 격리 보존(Backup)하는 방침을 구체화했습니다.
* **기존 요구사항 불변 확인:** 사용자 확정 결정(Q-1 ~ Q-6) 및 승인된 기능(REQ-01 ~ REQ-06), 제외 범위(EXC-01 ~ EXC-03)의 동작 사양과 인수 기준에 일체의 퇴행 없이 일관성을 유지했습니다.

---

## 1. 일상적인 예시로 보는 사용자 여정

사용자가 크롬, 엣지 등 웹 브라우저를 켜고 이 프로그램을 사용하는 일상적인 흐름입니다.

* **예시 1: 새 할 일 추가하기**
  * 사용자가 입력창에 제목(`우유 사기`), 마감 날짜 및 시간(`2026-11-10 18:00`), 메모(`저지방 우유로 사기`)를 적고 [추가] 버튼을 누릅니다.
  * 화면의 **'진행 중인 할 일'** 구역 맨 아래에 `우유 사기`가 즉시 나타납니다.
  * 이미 목록에 `우유 사기`가 있더라도, 필요하다면 똑같은 제목으로 한 번 더 등록할 수 있습니다.
* **예시 2: 완료 표시하고 되돌리기**
  * 마트에서 우유를 산 뒤, 목록에 있는 `우유 사기` 옆의 [완료] 버튼을 누릅니다.
  * 해당 항목이 '진행 중인 할 일' 구역에서 사라지고, 아래쪽 **'완료한 일'** 구역으로 이동합니다.
  * 만약 잘못 눌렀다면, '완료한 일' 구역에서 [완료 취소] 버튼을 눌러 다시 '진행 중인 할 일' 구역으로 되돌릴 수 있습니다.
* **예시 3: 내용 고치기와 지우기**
  * 마감 시간을 바꾸고 싶을 때 [수정]을 눌러 날짜와 시간을 고치고 [저장]하면 목록에 바뀐 내용이 반영됩니다.
  * 완전히 끝났거나 필요 없어진 항목의 [삭제]를 누르면, 브라우저에 **"정말 삭제할까요?"**라는 확인 창이 뜹니다. 여기서 확인을 눌러야만 목록에서 완전히 지워집니다. 취소를 누르면 아무것도 지워지지 않습니다.
* **예시 4: 프로그램을 껐다 켜도 유지하기**
  * 컴퓨터를 끄거나 웹 브라우저 창을 닫은 뒤, 다음 날 다시 프로그램을 열어도 어제 적어둔 할 일과 완료 목록이 그대로 남아 있습니다.

## 2. 요구사항 결정 사항 구분

### 2.1 사용자 확정 결정 (User Settled Decisions)
사용자가 직접 질의응답을 통해 확정한 내용이며, 기획의 기준이 됩니다.
* **실행 환경 및 저장소:** 웹 브라우저 환경에서 버튼과 입력창으로 사용하며, 외부 서버 없이 사용자의 로컬 컴퓨터에만 저장함 (출처: `Q-1`).
* **목록 분리 및 완료 취소:** '할 일'과 '완료한 일'을 분리하여 보여주며, 완료된 항목은 다시 미완료로 되돌릴 수 있음 (출처: `Q-2`).
* **수정 및 삭제 방식:** 등록된 내용 수정이 가능하며, 삭제 시에는 반드시 "정말 삭제할까요?" 확인 과정을 거침 (출처: `Q-3`).
* **기록 항목 및 필수 여부:** 제목(필수), 마감 날짜 및 시간(필수), 추가 메모(선택)를 입력함 (출처: `Q-4`).
* **목록 나열 순서:** '할 일'과 '완료한 일' 각 구역 내에서 최초 등록된 순서대로 표시함 (출처: `Q-5`).
* **중복 제목 허용:** 이미 같은 제목이 등록되어 있어도 각각 별개의 할 일로 중복 추가를 허용함 (출처: `Q-6`).

### 2.2 기획자 위임 설계안 (Delegated Design Proposals)
사용자가 구체적 방식을 기획에 위임(`Q-1`)함에 따라 안전하고 일관된 동작을 위해 제안하는 세부 설계입니다.
* **로컬 저장 기술:** 외부 설치 없이 웹 브라우저 표준 기능으로 작동하는 `로컬 저장소(localStorage)`를 활용합니다.
* **항목 고유 식별자:** 중복 제목을 구분하고 시계 조작이나 오차에 영향받지 않도록, 등록 시마다 1씩 증가하는 고유 번호(Sequence ID, 예: `1, 2, 3...`)를 부여합니다.
* **등록 순서 불변 기준:** 컴퓨터 시계가 과거로 변경되더라도 등록 순서가 뒤바뀌지 않도록, 최초 등록 시 발급된 고유 번호 순서(`createdAtSeq`)를 고정하여 정렬 기준으로 삼습니다.
* **확인 대화창 방식:** 브라우저 기본 확인 창(`window.confirm`)을 사용하여 실수로 인한 삭제를 방지합니다.

### 2.3 미해결 결정 사항 (Unresolved Decisions)
* 현재 승인된 Scope(v4) 및 사용자 결정(`Q-1 ~ Q-6`) 기준에서 필수적인 핵심 요구사항은 모두 정의되었습니다.
* **확인 필요 사항 없음:** 승인된 범위 내에서 온전히 구현 가능한 상태입니다.

## 3. 기능별 상세 사양 및 검증 기준

### REQ-01: 할 일 등록
* **정상 동작:**
  * 사용자가 제목과 마감 일시를 입력하고(메모는 선택 입력) [추가]를 누르면 새 항목이 생성됩니다.
  * 생성된 항목에는 고유 식별 번호(`id`, `createdAtSeq`)가 부여되며, 상태는 '진행 중'(`isCompleted: false`)으로 초기화됩니다.
  * 기존에 완전히 동일한 제목, 마감 일시를 가진 항목이 있더라도 거부하지 않고 별개의 새 항목으로 등록됩니다.
* **입력 검증 규칙:**
  * 제목: 공백을 제외하고 최소 1글자 이상이어야 합니다. 공백 문자만 입력된 경우 거부됩니다.
  * 마감 일시: 유효한 날짜 및 시간 형식이어야 하며 빈 값일 수 없습니다.
  * 메모: 입력하지 않아도 되며, 텍스트 입력을 허용합니다.
* **실패 및 무변경 동작:**
  * 제목이 비어있거나 마감 일시가 선택되지 않은 채 [추가]를 누르면 "제목과 마감 날짜/시간을 모두 입력해주세요." 안내 메시지를 띄우고 데이터는 추가되지 않습니다.
* **관찰 가능한 인수 검증 예시:**
  * [입력] 제목: `청소하기`, 마감: `2026-11-12 10:00`, 메모: (빈칸) 입력 후 [추가] 클릭.
  * [결과] '할 일' 영역 맨 아래에 `청소하기` 항목이 즉시 노출됨.
  * [연속 입력] 동일하게 제목 `청소하기`, 마감 `2026-11-12 10:00`을 다시 입력하고 [추가] 클릭 시, '할 일' 영역에 서로 다른 2개의 `청소하기` 항목이 나란히 존재함.

### REQ-02: 목록 분리 및 정렬 조회
* **정상 동작:**
  * 화면은 명확히 구분된 두 구역('진행 중인 할 일', '완료한 일')으로 나뉩니다.
  * 각 구역 내부의 항목들은 **최초 등록된 순서(고유 등록 번호 오름차순)**대로 일관되게 정렬되어 표시됩니다.
* **실패 및 무변경 동작:**
  * 등록된 항목이 없으면 각 구역에 "등록된 할 일이 없습니다" 또는 "완료한 일이 없습니다"라는 빈 상태 안내를 표시합니다.
* **관찰 가능한 인수 검증 예시:**
  * 1번 `책 읽기`, 2번 `운동하기` 순으로 등록된 상태에서 목록을 볼 때, '진행 중인 할 일' 구역에 상단 `책 읽기`, 하단 `운동하기` 순서로 일관되게 표시됨.

### REQ-03: 완료 처리 및 완료 취소
* **정상 동작:**
  * '진행 중인 할 일' 구역의 항목에서 [완료] 버튼을 누르면 상태가 완료(`isCompleted: true`)로 변경되고, 즉시 '완료한 일' 구역으로 이동합니다.
  * '완료한 일' 구역의 항목에서 [완료 취소] 버튼을 누르면 상태가 미완료(`isCompleted: false`)로 변경되고, 즉시 '진행 중인 할 일' 구역으로 복귀합니다.
  * 상태가 변경되어도 항목의 최초 등록 번호(`createdAtSeq`)는 유지되므로, 각 구역 내에서 본래의 등록 순서 위치를 지킵니다.
* **실패 및 무변경 동작:**
  * 이미 완료된 항목에 완료 요청을 보내거나 미완료 항목에 취소 요청을 보내는 비정상 상태 전이는 무시되며 데이터가 변경되지 않습니다.
* **관찰 가능한 인수 검증 예시:**
  * [동작 1] '진행 중인 할 일'의 `우유 사기` 옆 [완료] 클릭.
  * [결과 1] '진행 중인 할 일'에서 사라지고 '완료한 일' 구역으로 이동함.
  * [동작 2] '완료한 일' 구역의 `우유 사기` 옆 [완료 취소] 클릭.
  * [결과 2] '완료한 일' 구역에서 사라지고 '진행 중인 할 일' 구역으로 다시 돌아옴.

### REQ-04: 할 일 수정
* **정상 동작:**
  * 항목의 [수정] 버튼을 누르면 기존 제목, 마감 일시, 메모가 입력창에 채워집니다.
  * 내용을 변경하고 [저장]을 누르면 해당 항목의 정보가 갱신되고 목록 화면에 즉시 반영됩니다.
  * 수정 시 항목의 고유 ID 및 최초 등록 순서 번호(`createdAtSeq`)는 절대 변경되지 않습니다.
* **입력 검증 규칙:**
  * 등록 시와 동일하게 제목(공백 제외 1자 이상)과 마감 일시는 필수입니다.
* **실패 및 무변경 동작:**
  * 수정 중 제목을 지우거나 마감 일시를 비운 채 저장을 누르면 경고를 표시하고 저장을 거부하며 기존 내용이 유지됩니다.
  * 수정을 취소하면 기존 값이 그대로 보존됩니다.
* **관찰 가능한 인수 검증 예시:**
  * [동작] `우유 사기`의 [수정] 클릭 후 마감 일시를 `2026-11-15 12:00`으로 변경 후 [저장] 클릭.
  * [결과] 화면상의 마감 일시가 `2026-11-15 12:00`으로 즉시 변경되고, 목록 내 위치와 ID는 유지됨.

### REQ-05: 삭제 확인 및 제거
* **정상 동작:**
  * 항목의 [삭제] 버튼을 누르면 "정말 삭제할까요?"라는 브라우저 확인 안내 창이 나타납니다.
  * 사용자가 [확인]을 누르면 해당 항목은 메모리와 저장소에서 완전히 삭제되며 목록에서 사라집니다.
* **실패 및 무변경 동작:**
  * 안내 창에서 [취소]를 누르거나 창을 닫으면 아무런 작업도 수행하지 않으며, 항목은 그대로 목록에 남습니다.
* **관찰 가능한 인수 검증 예시:**
  * [동작 1] `방 청소` 항목의 [삭제] 클릭 후 확인 창에서 [취소] 선택.
  * [결과 1] `방 청소` 항목이 지워지지 않고 목록에 그대로 존재함.
  * [동작 2] 다시 [삭제] 클릭 후 확인 창에서 [확인] 선택.
  * [결과 2] `방 청소` 항목이 목록에서 완전히 제거됨.

### REQ-06: 데이터 로컬 지속성
* **정상 동작:**
  * 데이터 변경(등록, 수정, 삭제, 완료, 완료 취소) 시마다 브라우저 저장소(`localStorage`)에 즉시 동기 기록됩니다.
  * 브라우저 창을 닫거나 컴퓨터를 재부팅한 후 다시 접속해도 이전 상태(항목 정보 및 진행 중/완료 분류)가 그대로 복원됩니다.
* **관찰 가능한 인수 검증 예시:**
  * [동작] 항목 2개 등록 및 1개 완료 처리 후 웹 브라우저 창을 완전히 닫음.
  * [동작] 브라우저를 다시 켜서 해당 프로그램을 엶.
  * [결과] 닫기 직전의 '진행 중인 할 일' 1개와 '완료한 일' 1개가 등록 순서 그대로 다시 표시됨.

## 4. 데이터 보존 및 무결성 관리 사양

### 4.1 데이터 구조 및 식별자 규칙
* **단일 항목 데이터 구조 (JSON 모델):**
  ```json
  {
    "id": 1,
    "title": "문서 작성하기",
    "dueDateTime": "2026-11-10T15:00",
    "memo": "검토용 초안 작성",
    "isCompleted": false,
    "createdAtSeq": 1
  }
  ```
* **식별자(Identity) 불변식:** `id`와 `createdAtSeq`는 항목 등록 시 자동 채번되는 양의 정수(1부터 시작)이며, 항목 수정 시 절대 변경되지 않습니다.
* **컬렉션 저장 키:** 브라우저 로컬 저장소 키 `my_todo_items_v1` 및 채번 카운터 키 `my_todo_seq_v1`을 사용합니다.

### 4.2 시스템 시계 독립적 순서 보장
* 컴퓨터 시계의 수동 변경, 오작동, 서머타임 등으로 인한 정렬 왜곡을 방지하기 위해, 시간 기반 타임스탬프 대신 1씩 증가하는 **순차 번호(`createdAtSeq`)**를 정렬 키로 사용합니다.

### 4.3 저장 데이터 검증 및 손상 처리 정책
브라우저 로컬 저장소 키(`my_todo_items_v1`)를 읽을 때 발생 가능한 데이터 상태를 다음과 같이 엄격히 구분하여 처리합니다.

* **1. 데이터 부재 (Absent Data):**
  * 저장소에 해당 키가 존재하지 않는 경우(`null`).
  * 정상적인 최초 실행 상태로 간주하고, 오류 없이 빈 목록(`[]`)으로 시작하며 채번 카운터는 0으로 초기화합니다.
* **2. 키는 존재하나 빈 값인 경우 (Present Empty):**
  * 키가 존재하지만 값의 내용이 비어 있거나(`""`) 공백 문자열인 경우.
  * 데이터 파괴 방지 원칙에 따라 임의로 덮어쓰지 않고, 비어 있는 비정상 문자열을 백업 키(`my_todo_items_empty_backup_[일시]`)로 격리 보존한 후 빈 목록으로 안전하게 시작합니다.
* **3. 데이터 손상 및 유효하지 않은 스키마 (Corrupt/Invalid Data):**
  * 로컬 저장소의 텍스트가 유효한 JSON 배열 형식이 아니거나, 배열 내부 객체에 필수 속성(`id`, `title`, `dueDateTime`, `isCompleted`, `createdAtSeq`)이 누락 또는 오염된 경우.
  * **비파괴 복구 원칙:** 기존 사용자 데이터를 절대 자동으로 덮어쓰거나 초기화(삭제)하지 않습니다.
  * 손상된 원본 데이터를 백업 키(`my_todo_items_backup_[일시]`)로 즉시 격리 복사한 뒤, 사용자 화면에 "저장된 데이터를 불러오는 중 이상이 감지되어 원본을 안전하게 백업 보관했습니다."라는 안내를 표시하고 동작을 안전하게 보호합니다.
* **4. 정상 데이터 (Valid Data):**
  * 모든 필수 속성과 형식이 일치하는 JSON 배열인 경우 정상적으로 메모리에 적재하여 화면에 등록 순서대로 표시합니다.

### 4.4 저장 커밋 경계 및 한계
* **커밋 경계:** 추가, 수정, 상태 변경, 삭제 등 모든 데이터 조작은 브라우저 메모리 반영과 로컬 저장소 저장이 단일 동기 작업(한 묶음)으로 즉시 완료됩니다.
* **현실적 한계:**
  * 단일 브라우저의 로컬 저장소를 사용하므로, 사용자가 브라우저 '인터넷 사용 기록/사이트 데이터 삭제'를 직접 실행하거나 비밀 모드(시크릿 창)를 닫는 경우에는 브라우저 자체 격리 정책으로 인해 데이터가 유지되지 않습니다.

## 6. 쉬운 용어 사전 (Glossary)

* **웹 브라우저 (Web Browser):** 인터넷과 웹 페이지를 볼 때 사용하는 프로그램(예: 크롬, 엣지, 사파리, 웨일 등)입니다.
* **로컬 저장소 (Local Storage):** 외부 서버로 정보를 보내지 않고, 사용자의 컴퓨터 웹 브라우저 내부에 글자 형태로 안전하게 보관하는 전용 저장 공간입니다.
* **순차 번호 (Sequence ID):** 컴퓨터 시계가 맞지 않거나 변경되어도 등록 순서가 뒤섞이지 않도록, 할 일이 추가될 때마다 1번부터 차례대로 매겨지는 번호표입니다.
* **데이터 검증 (Validation):** 사용자가 빈칸으로 등록하거나 잘못된 형식으로 입력하지 못하도록 프로그램이 사전에 확인하고 막아주는 규칙입니다.
* **비파괴 보존 (Non-destructive Preservation):** 저장된 데이터에 문제가 생겼을 때, 사용자의 기존 데이터를 함부로 지우거나 초기화하지 않고 별도의 안전한 장소에 백업해 두는 보호 방식입니다.
