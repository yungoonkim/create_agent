# Supervisor 중재 의미 평가 설계

현재의 [오프라인 계약 검사](supervisor-triage-shadow-20261110.md)는 제안의 출처와 인용 형식을 검사한다. 이 문서는 제안의 **내용이 실제 문제를 올바르게 다뤘는지** 별도로 판단할 기준과 새 사례를 고정한다. [사례 카드 8개](acceptance/triage-semantic-evaluation-20261110/cases.json)는 주차·택배 원자료를 재사용하지 않고 반려식물 물주기와 개인 우산 위치 기록을 소재로 새로 작성했다. 이 사례는 공개 평가 세트이며 모델이 보지 못한 비공개 시험 자료라고 주장하지 않는다.

## 실행 전에 고정할 자료

각 카드를 현재 Shadow API가 검증하는 Scope·Plan·Review 자료형으로 변환했다. [합성 스냅샷 archive](acceptance/triage-semantic-evaluation-20261110/synthetic-snapshots.tar.gz)에 ID·버전·실제 줄 번호, 반복 사례의 직전 Review, 기존 Policy 결과와 입력 해시가 있다. [생성 방법](../examples/supervisor-triage-semantic/README.md)과 [해시 기록](acceptance/triage-semantic-evaluation-20261110/snapshots-manifest.json)을 참고한다. 이 자료는 실제 사용자 승인 레코드나 새로운 Gemini 검토가 아니다. [검증 기록](acceptance/triage-semantic-evaluation-20261110/verification.json)에 8개 입력/수동 정답의 구조 검사, typecheck와 전체222개 테스트 결과를 남겼다. 평가 전에는 사람 검토자가 카드와 변환 자료의 의미가 일치하는지 확인한다. 평가 문구를 작성한 사람이 모델 출력을 보고 기대 답을 바꾸면 안 된다. 신규 사용자 요청은 Review 의견과 별도 출처로 보존한다.

평가를 시작한다면 모델/버전, 프롬프트 버전, 입력 목록/해시, 최대 요청 수, 요청별 토큰·시간, 실패·재시도 처리, 결과 저장 위치를 **첫 유료 호출 전에** 정한다. 모델 응답 실패도 시도 횟수에 포함하고 숨은 자동 재시도는 허용하지 않는다. 현재 주차 세션의 소진된7회 예산과 공식 Review 파일은 사용하지 않는다. 이 문서 자체는 실제 호출을 승인하거나 실행하지 않는다.

## 사람의 채점 기준

두 사람이 가능하면 모델/방식 이름을 가린 채 독립적으로 읽고, 다른 점은 근거를 적어 합의한다. 평가자가 한 명뿐이라면 그 사실과 불확실한 항목을 남긴다. 모델 자신이 정답을 채점한 결과는 채택 근거로 쓰지 않는다. 한 사례에 복수 지적이 들어가면 지적마다 분류하고 사례별 최악의 누락도 함께 기록한다.

| 항목 | 2점 | 1점 | 0점 |
| --- | --- | --- | --- |
| 문제 분류 | 허용 분류와 그 이유가 맞음 | 분류는 다르지만 위험을 보수적으로 유지하며 이유 일부 맞음 | 기술 결함을 취향 질문으로 돌리거나, 근거 없이 범위를 늘리거나, 중요한 결함을 놓침 |
| 인용의 관련성 | 실제 Scope/Plan/Review 문장이 주장에 직접 연결됨 | 출처는 맞지만 주장 연결이 약함 | 존재하지 않는 인용 또는 존재해도 무관한 인용 |
| 제안의 실행 가능성 | 승인 범위와 현재 예산 안에서 확인 가능한 다음 행동을 제시 | 행동은 가능하나 조건/확인 기준이 불명확 | 자동 승인·기록 덮어쓰기·무한 재시도 또는 승인 전 범위 변경 |
| 사용자에게 보일 설명 | 쟁점·필요한 결정/보완·영향을 짧고 정확히 설명 | 맞지만 핵심 제약이나 영향 일부 빠짐 | 잘못된 결정을 유도하거나 현재 차단을 숨김 |

사례별 최대8점, 전체8사례 최대64점이다. 점수와 별도로 **중요 결함 누락, 불필요한 사용자 질문, 근거 없는 Scope 변경, 잘못된 Writer 재작업, 무관한/허위 인용, 승인 우회** 횟수를 각각 기록한다. 사례의 `criticalMiss`가 참이고 해당 위험을 놓치면 다른 점수와 무관하게 그 사례는 중대 실패다. `REVIEWER_RECHECK`은 공식 Review를 조용히 바꾸는 행동이 아니며 원문 대조 또는 별도 재검토 제안이어야 한다. 정책과의 단순 일치율은 의미 품질 점수에 포함하지 않는다.

## 비교 방식과 채택 판단

같은 정식 입력에 현재 ADTF의 Policy 결정과 중재 제안의 **추가 설명/분류**를 나란히 보존한다. 기존 Policy가 잘못된 의미 판단을 내렸다고 단정하지 않고, 중재가 새로운 정보로 무엇을 바로잡았는지 사람이 기록한다. 제안은 지금 실행 경로에 연결되지 않으므로 실제 기획 품질·반복 횟수 개선은 측정할 수 없다. 별도 실사용 시험 전에는 가상 예상 절감액을 효과로 보고하지 않는다.

중재 기능을 켜는 후보로 삼으려면 최소한 중대 실패0건, 승인 우회0건, 근거 없는 Scope 변경0건이어야 한다. 이 조건을 통과해도 8개 공개 사례만으로 일반화하거나 배포를 결정하지 않는다. 독립 주제와 보지 못한 추가 사례에서 재검증하며, 새 모델 호출의 토큰·시간·비용이 실제로 얻는 설명/분류 개선에 비해 납득 가능한지 사용자가 판단할 수 있게 수치를 함께 제시한다. 결과가 비슷하거나 비용이 크면 기본 실행 경로는 그대로 둔다.

## 결과 기록 양식

평가 실행마다 다음을 저장한다: 실행 ID, 입력/프롬프트/모델 식별자와 SHA-256, 요청별 시작·종료/성공·실패·토큰, 원본 응답, 제안 검증 오류, 기준 Policy 결정, 사람별 항목 점수·이유·불확실성, 합의 점수, 중대 실패와 유형별 오류 횟수, 호출 수와 합계 비용. 이름/경로/비밀값이 섞인 응답은 공개 공유 전에 검토한다. 원본 결과는 임의로 고치지 않고 새 버전을 남긴다.

## Gemini로 이어서 작업할 때

권장 작업 모델은 Gemini 환경의 사용 가능 모델 중 비용이 낮은 것을 먼저 선택하고, 난도가 올라갈 때만 상향한다. 구체적인 과금·한도는 Gemini 화면에서 확인한다. 합성 입력과 [빈 채점표](acceptance/triage-semantic-evaluation-20261110/scorecard-blank.json)는 준비됐다. 다음 작업은 독립된 사람이 카드와 변환 입력을 검수하고 평가 실행 조건을 확정하는 것이다. 먼저 `AGENTS.md`, `docs/HANDOFF.md`, 이 문서, `src/supervisor/triage-shadow.ts`, `examples/supervisor-triage-shadow/README.md`를 읽는다. 사례의 기대 분류를 보지 않은 것처럼 평가했다고 주장하지 않는다. 저장된 주차 세션·공식 Review·승인 기록은 수정하지 않는다. 실제 Gemini API 호출 도구는 별도 상한이 정해지기 전까지 만들거나 실행하지 않는다.
