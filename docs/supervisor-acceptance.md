# 현재 지휘자 겸 기획자 Agent 완료 기준

기준일: 2026-11-08 (한국 시간)

## 현재 목표

지휘자 겸 기획자 Agent 하나가 사용자의 모호한 요청을 구체적인 기획·작업 지시로 발전시키고, 승인·변경·오류를 올바르게 처리하며, 진행 상황을 사실대로 설명하는지 검증한다. 사용자 최신 지시에 따라 팀원 Agent의 설계·개발·연결과 기타 확장 작업은 보류한다. 시험 완료를 다음 확장의 자동 시작 조건으로 쓰지 않는다.

Writer와 Reviewer는 현재 Agent의 내부 기획 역할이다. 기존 수동 개발·검증 기능은 Agent의 판단을 시험하는 기반으로 사용하며, 테스트용 보고는 TEST/STUB로 표시한다.

## 실제 시험 방법

1. Cloud의 GCP 인증·접속을 연결하고 현재 인수 요청에서 실제 질문을 생성한다. 현재 모델 호출은 인증·네트워크 연결 대기다.
2. [재고·유통기한 시나리오](supervisor-test-plan.md)를 사용해 질문·Scope·기획·검토·작업 지시를 평가한다. 실제 생성된 승인 대상을 검토한 뒤 해당 결정을 기록한다.
3. lot별 날짜 보존, 정수·음수 수량, 만료·임박 경계, 기준일·정렬·저장 오류가 기획·지시서에 충분히 반영되는지 확인한다. 제외 기능이 추가되면 이슈로 기록한다.
4. 추가 답변·변경 승인·거절과 실패·중단 정책을 각각 확인한다. 의도한 실패가 모델에서 자연 발생하지 않으면 정책 시험 fixture를 사용한 사실을 표시한다.
5. 발견한 문제를 현재 Agent에서 수정하고 회귀 검증한다. 준비된 환경에서 별도 실행 ID로 동일 주제를 다시 시험해 결과와 수정 횟수를 비교한다.
6. 실행별 원문·답변·Scope/Plan/Review·결정·작업 지시·검사·미실행 항목·한계를 문서로 남긴다. 실행하지 못한 항목은 합격으로 바꾸지 않는다.

## 현재 판정

- 기존 자동 검증: 전체 111개 테스트 통과. 정책·저장·CLI 및 fixture를 포함한 결과다.
- 실제 Gemini 전체 기획 품질: 미평가. Cloud ADC와 Vertex AI/OAuth 접속 설정 대기다.
- 현재 Agent 전체 완료: 인수 대기. 위 실제 품질 평가와 수정·재시험 결과를 확인한 뒤 판정한다.
- 알려진 동작: 명령을 단계별로 실행하는 CLI다. 모델 호출 도중 중단된 실행은 자동 재호출하지 않고 중단 상태를 보존한다. 이미 제안/초기화한 작업의 범위 변경·이관은 지원하지 않는다. 이 한계들을 숨기지 않고 시험 결과에 명시한다.

실행 현황은 [Gemini 인수 기록](gemini-acceptance-status.md), Cloud 준비는 [인증·접속 설정](cloud-gcp-setup.md), 세부 명령은 [사용법](supervisor-workflow.md)에 정리했다.
