# 택배 v2 반례 호환성 후보 단일 실행 준비

이전 반례 요청의 `INVALID_ARGUMENT` 원인은 불명이다. PR #17의 오프라인 후보는 전송용 `responseJsonSchema`만 제거하고 JSON MIME을 유지한다. 이번 실행기는 기존 일반 검토 성공 응답을 재사용한 뒤 원래 실패 반례 요청의 해시를 확인한다. 새 요청이 고정 후보와 정확히 일치할 때만 SDK로 전송한다. 현재 시험 준비에서 실제 Gemini/OAuth 요청은 0회다.

기존 후속·진단 5회와 실패한 반례 1회로 관련 이력은 6시도(최초 인증 실패 시도는 별도)다. `--run-live`는 **새 추가 상한 최대1회**, 실행 시 합계 최대7시도다. 이전 실행 폴더/원자료/시작 예약은 건드리지 않는다. 새 실행의 별도 시작 예약은 같은 폴더에서 두 번째 유료 시작을 막고 SDK 자동 재시도는 1로 고정된다. 폴더를 복사하거나 새로 만들면 전역 과금 한도는 강제되지 않는다.

전송 스키마가 없어지면 모델 출력이 기존 형식을 어길 수 있다. 기존 production Reviewer의 JSON 파싱, 필수 필드, 정확한 줄·출처·저장 사례 검증, 정책 판단은 유지한다. 실패는 응답/허용목록 오류와 요약을 보존하고 멈춘다. 유효한 Review도 **분리한 DEMO FIXTURE 복사본**에만 저장하고 최종 사용자의 승인은 자동 생성하지 않는다. Writer·Scope·원본 프로젝트를 변경하지 않는다. 성공/품질은 사용자 실실행 결과를 보기 전까지 미확정이다.

[Windows 실행 안내](../examples/parcel-challenge/README-no-schema.md). 전체186개 오프라인 검사와 타입 검사 통과. 실행용 ZIP은 소스 커밋·파일 해시를 manifest로 고정하고 기록 의존 테스트를 제외한다. ZIP 패키지의 검사 수와 dry-run 결과는 별도 검증 기록에 남긴다.
