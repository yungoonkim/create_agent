# 택배 v2 반례 검토 재개 준비

2026-11-10. 일반 검토 성공 응답을 재사용하고 반례 검토만 새로 받는 별도 실행기를 준비했다. 이번 준비 작업에서 실제 Gemini/OAuth 호출은 0회다.

## 입력과 예산

`examples/parcel-challenge/source.json`은 실제 후속 실행의 v1/v2·이전 Review 문맥과 실제 후보 진단의 요청/응답을 SHA-256으로 고정한다. 일반 검토는 같은 production adapter에서 다시 파싱·검증하지만 네트워크 대신 기록된 응답을 공급한다. 재구성한 요청이 기록과 다르면 추가 호출 전에 멈춘다. 원래 진단에 사용된 200초 전송 timeout을 동일하게 붙여 비교한다. 과거 토큰 메타데이터는 출처 파일에 보존하되 새 usage에 재합산하지 않는다.

기존 후속3+동일 요청 진단1+후보1=5회는 소진된 이력이다. 이번 `--run-live`는 **새 상한 최대1회**를 명시하는 별도 단계이며 합계 최대6회다. 더 앞선 최초 인증 실패1시도는 별도 기록이다. 한 폴더에서 단일 시작 예약과 SDK retry attempts=1로 추가 재실행을 막는다. 다른 폴더까지 적용되는 전역 결제 한도는 아니다. 실패나 지적이 있어도 Writer/일반 검토/다른 유료 요청을 이어 실행하지 않는다.

## 저장과 승인

기존 프로젝트 폴더를 건드리지 않고 새 `challenge-results`의 분리한 저장소에 기존 본문을 복사한다. Scope 승인은 실제 사용자 승인이 아닌 **DEMO FIXTURE**다. 반례 응답의 구조·인용·이력 검증까지 성공하면 그 복사본에만 정식 Review를 저장한다. 정책이 허용할 때 pending 승인과 사용자 검토표를 만들며 **최종 승인은 만들지 않는다**. 미해결 지적은 기존 v2/2라운드 한도를 적용해 정지하거나 사용자 답변 대기로 기록한다. 제품/팀원 실행은 없다.

특정 택배 시험의 이어가기이며 일반 프로젝트의 자동 복구 기능은 아니다. 모델의 의미 판단·검증 규칙 완전성은 코드가 증명하지 않으며, 일반 검토의 한 번 pass도 품질 보증이 아니다.

## 검증 및 배포

타입 검사와 전체183개 오프라인 검사 통과. 새5개 검사는 응답 재사용/사용량 분리, 요청 불일치 시 호출0회, HTTP 및 불완전 출력의 재시도 방지, 차단 지적의 승인 방지, 중복 시작 예약 보존을 확인한다. TEST/STUB으로 정책 분기를 확인한 것이며 실제 LLM의 반례 탐지 결과가 아니다.

짧은 경로 ZIP은 `parcel-challenge` 프로필로 만들어 시작 명령을 `complete:parcel-review`에 한정한다. 모델 호출 없는 dry-run은 의도적으로 검토 미확인 지적을 남겨 `limit_reached`로 정지한다. 실제 실행 후 원압축과 근거를 보존하고 다시 판단한다. [실행 방법](../examples/parcel-challenge/README.md), [패키지 검증 기록](parcel-challenge-validation-20261110.json).
