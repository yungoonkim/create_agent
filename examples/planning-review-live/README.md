# 사용자 검토표 실제 Gemini 재시험

기존 검토표·신뢰성 보완을 새 두 사례로 확인한다. 새 식물 물주기 기록은 실제 Writer부터 기획·검토·내보내기를 실행한다. 운동 기록은 **고의로 범위 밖 공개 서버 전송을 넣은 고정 초안**에서 시작해, 실제 Reviewer·Writer가 Scope를 바꾸지 않고 교정하는지 확인한다. 고정 초안을 모델이 처음 작성했다고 주장하지 않는다.

입력/기준/생산 코드/실행기/요금표를 실제 생성 전에 고정했다. 실제 결과의 근거 적합성과 기존 요구 보존은 진행자가 마지막으로 원문 감사한다. 결과 파일의 상태나 모델 pass만으로 품질 합격을 선언하지 않는다. 일반 채팅 대비 우열 시험도 아니다.

## 사용자 PC에서 실행

사용자 검토표와 이 재시험 도구가 포함된 최신 소스를 새 폴더에 받고, 기존 프로젝트 폴더는 그대로 보관한다. Windows CMD/PowerShell 어느 쪽에서도 다음과 같이 실행한다. Node.js24 권장, 기존 PC의 ADC 로그인을 사용하며 Cloud의 인증 파일을 복사하지 않는다.

```powershell
npm.cmd ci
npm.cmd run eval:planning-review -- generate --run-live --bundle
```

환경변수나 PowerShell 변수가 필요 없다. 프로젝트 `iceu-songpa11`, 위치 `global`, Writer/Reviewer `gemini-3.8-flash`를 고정 설정에서 명시한다. 실행 이름도 자동 생성한다.

`--run-live`는 Google Cloud에 과금될 수 있는 일괄 실행 동의이며 별도 CALL 입력은 없다. 상한은 **최대11 SDK 요청**이다. 식물 기획은 최대2회 작성/각2회 검토로6회, 운동은 고정 초안의 검토 최대2회+수정 작성1회+수정본 검토2회로5회다. 일찍 통과/중단하면 줄어든다. 추가 유료 채점 API는 호출하지 않는다. 요금은 제공된 토큰과 스냅샷 요금표로 소계만 기록하며 청구서 금액을 보증하지 않는다.

요청 시작마다 사례·단계·요청 수를 출력한다. 끝의 `RESULT_ARCHIVE=...`에 표시된 `.tar.gz` **파일 하나**를 전달한다. 원요청/응답·모든 초안/Review·부분 응답/실패·사용량·기획 원문·검토표·해시를 함께 담는다. ADC·환경변수 값·HTTP 인증 헤더는 넣지 않는다. 실제 Scope/기획 사용자 승인·제품/팀원 실행은 하지 않는다.

## 실패해도 다시 실행하지 않기

같은 고정 시험은 체크아웃당 한 번만 live 실행할 수 있다. 호출 전에 시작 예약을 저장하며 실패해도 삭제/초기화하거나 새 이름으로 재생하지 않는다. 실패·질문·Scope 판단 대기·한도 도달도 기록으로 남기며 성공적인 검토 완료로 세지 않는다. 이 경우 종료 코드2여도 압축 파일은 만들어질 수 있으므로 결과 파일을 전달한다. 인증/권한 실패는 나머지 사례 호출도 중단한다.

압축 생성 단계만 실패했다면 화면에 나온 실행 ID로 모델 호출 없는 패키징만 수행한다.

```powershell
npm.cmd run eval:planning-review -- pack --run-id "화면에 나온 실행ID"
```

기존 압축도 덮어쓰지 않는다. 압축 생성 오류가 반복되면 원자료 폴더와 오류를 보존해 전달한다. 유료 생성을 다시 실행하지 않는다.

## 오프라인 확인과 결과 무결성

```sh
npm run build
node examples/planning-review-live/run.mjs dry-run --bundle
node examples/planning-review-live/run.mjs verify --run-id EXISTING_ID
```

dry-run은 고정 응답이며 실제 Gemini나 의미상 품질 증거가 아니다. verify/pack은 기존 파일 해시만 확인하고 모델을 호출하지 않는다. 생성과 달리 현재 생산 소스를 재실행하지 않으며 당시 실행기/고정 설정을 대조한다.

Cloud에서는 ADC 재인증 필요와 공유 공식 Google 로그인 브라우저의 `Browser Use could not read requirements` 오류를 확인해 실제 생성하지 못했다. 로그인 코드/토큰을 채팅에 요구하거나 TLS·네트워크 정책을 우회하지 않았다. 인증된 PC의 결과를 받은 뒤 원문 근거·수정 효과·중단·사용량을 감사한다.
