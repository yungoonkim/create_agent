# Supervisor 중재 오프라인 모의 평가

추가 모델 호출 없이 **사람이 작성한 제안의 계약과 근거 연결**을 검사한다. 실제 중재 모델의 의미적 분류 정확도나 품질 향상을 평가한 것으로 해석하지 않는다. Controller·Policy 실행 경로에 연결하지 않았으며 공식 Review·Plan·승인·예산을 쓰는 기능이 없다.

전체 Git 저장소의 package.json 폴더에서 실행한다. 원자료가 없는 짧은 실행 ZIP용 명령은 아니다.

```powershell
npm.cmd run eval:triage-shadow -- --output C:\adtf-data\triage-shadow-01
```

출력은 **존재하지 않는 새 폴더**여야 한다. 기존 출력은 덮어쓰지 않는다. `--run-live` 옵션이나 인증은 없다. 기존 주차 세션 폴더를 옮기거나 초기화할 필요가 없다.

고정 SHA-256의 저장된 주차 archive를 임시 복사본에서 읽는다. 기준 Policy 결정을 먼저 계산하고, 원시 Review 지적 외에도 저장·품질·보존 검사와 질문·제안을 모두 독립 출처 ID로 포함한다. Plan 줄·Scope 항목·각 지적의 실제 텍스트와 입력 해시를 묶는다. 입력 Scope가 승인됐다는 사실은 호출자의 전제이며 이 도구가 사용자 승인을 만들어내거나 인증하지 않는다.

제안은 입력 해시, 모든 지적의 일대일 포함, 기존 참조, 각 지적+Plan/Scope의 인용을 요구한다. 기술적 차단을 사용자 취향/Scope 변경으로 바꾸는 제안은 거부한다. Scope 변경 제안에는 별도 사용자 요청의 인용이 필요하지만 그것만으로 의미적 타당성이나 변경 승인이 성립하지 않는다. 모르는 필드를 거부하므로 실행/승인 권한을 제안에 추가할 수 없다.

성공 상태인 `structurally_valid_for_manual_inspection`도 **구조/참조 검사 통과**일 뿐이다. 존재하는 줄을 엉뚱하게 인용하거나 rationale/proposedAction에 잘못된 주장을 쓸 수 있으므로 내용은 사람이 대조해야 한다. 해시는 변경 감지용이며 서명이나 출처 인증이 아니다. 제안을 실행 결정으로 매핑하지 않는다. 분류와 Policy가 달라도 Policy가 유지된다.

출력: input/context/proposal/cases/report JSON과 파일 해시 manifest. 주차의 수동 재검토 예시1개 및 거부 예시6개를 함께 보존한다. 지적 누락, 오래된 입력, 잘못된 줄, 취향 질문으로의 격하, 승인 권한 추가, 근거 없는 Scope 요구를 시험한다. 테스트에는 정상 질문·Scope 요청·반복/한도·품질/보존 지적 누락도 포함한다. 공개 고정 사례이므로 미공개 검증 세트나 독립 정답 데이터가 아니다.

이후 별도 실모델 평가를 한다면 모델/프롬프트·새 호출 상한·실패 예약·입력 해시·응답 원문·토큰/시간을 먼저 고정해야 한다. 새로운 주제의 독립 사례에 대해 사람이 정한 기대 분류와 비교하고, 잘못된 재작업·불필요한 질문·Scope 확장·중요 결함 누락·인용의 관련성·추가 비용을 측정한다. 같은 모델의 자기 채점이나 Policy 일치율만으로 도입하지 않는다. 현재 소진된 주차7회 예산을 재사용하거나 정식 Review를 덮어쓰지 않는다.

입력 보완: 선택적 직전 Plan을 제공하면 같은 Scope의 직전 버전과 이전 Review의 출처를 검증한다. `previous-plan:L번호`, `previous-review:issue:ID`, `iteration:state`를 인용할 수 있다. 이전 Review만 있는 경우 원문 부재를 `history:availability`에 표시한다. [v2 점검](../../docs/triage-semantic-audit-20261110.md).
