# 내 할 일 목록 관리

## 사용자가 동의한 요청

혼자 쓸 할 일 관리 도구를 만들고 싶어. 할 일을 추가하고, 목록을 보고, 끝난 일은 완료로 표시하고 싶어. 프로그램을 껐다 켜도 내용이 남았으면 좋겠어.

## 이번 시험의 표현 방식과 실행 경계

- 사용자는 이전 재고 주제의 기술적인 내용을 이해하기 어려워했다. 질문·Scope·기획안·작업 지시는 쉬운 한국어와 일상적인 사용 예시 중심으로 작성한다.
- 예: ‘장보기 추가 → 목록에서 확인 → 완료 표시 → 다시 켜도 유지’. 중요한 선택에는 사용자가 결과를 상상할 수 있는 짧은 예시를 든다.
- 기획안의 사용자 동작 설명을 먼저 두고, 구현에 필요한 기술 세부사항은 별도 절로 구분한다. 기술 용어가 필요하면 뜻을 함께 설명한다.
- 아직 정하지 않은 수정·삭제·마감일·정렬·완료 취소·이용 화면 등의 선택을 확정 요구로 가정하지 말고, 실제 기획에 영향을 주는 선택은 사용자에게 질문한다.
- 이 실행은 지휘자·기획자 단독의 질문·Scope·기획·검토·작업 지시 품질 시험이다. 제품 구현이나 팀원 Agent 실행은 하지 않는다. 제품 구현을 위한 기획·작업 지시 작성은 시험에 포함한다.
- Scope와 최종 기획안은 각각 사용자가 원문을 검토한 뒤 승인한다. ‘진행해줘’는 아직 생성되지 않은 Scope·기획안의 승인이 아니다.
