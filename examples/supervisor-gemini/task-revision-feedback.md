인수시험 진행자의 작업 지시 품질 점검이다. 승인된 Scope v4와 기획안 v3은 변경하지 않는다.

1. 파서 작업의 '모든 수치 연산 결과는 0 이상'이라는 문구가 음수 증감량을 금지하는 것으로 읽히지 않도록 고친다. 수량·N·변경 후 재고는 0 이상의 안전 정수이고, 증감량 자체는 음수·0·양수 안전 정수를 허용한다. 입력 문자열 표기 검증과 숫자 값 검증을 구분한다.
2. CLI 작업 지시에서 실제 서브커맨드, 필수/선택 플래그, 기본 JSON 파일 경로, 경로 재지정 방법, 성공/입력 오류/저장 결과 불확실성의 출력·종료 규칙을 확정한다. '작업자가 추후 결정'으로 다시 미루지 않는다. 승인된 로컬 CLI 범위 안의 상세 설계로만 정한다.
3. 최초부터 실행 가능한 미래 제품 구성이 되도록 필요한 package.json, tsconfig.json 등 빌드 설정 산출물과 CLI 실행 방법도 어느 작업이 담당하는지 연결한다. 이 저장소의 프레임워크 코드에 제품 코드를 만드는 명령으로 해석하지 않는다.
4. 저장 작업은 version=1/lots 배열 루트, 필수 필드 타입·값·중복 lotId 검증, 파일 fsync·rename·지원 환경의 부모 디렉터리 fsync, 실패 경계, cleanup 실패·SIGKILL 한계·임시 파일 자동 승격 금지를 명시한다. 검증 방법이 rename 이후 동기화 실패에도 '원본 불변'을 요구하는 모순을 만들지 않도록 한다.
5. 지시서에 실행 예와 예상 결과를 넣는다. 기준일 2026-11-08, N=2에서 LOT-A(3개, 11-07)는 만료, LOT-B(5개, 11-08)·LOT-C(2개, 11-10)는 임박, LOT-D(4개, 11-11)는 대상 밖, LOT-E(0개, 11-09)는 제외다. LOT-B에 -2를 반영하면 3, 이어 -4는 거부하고 3을 유지한다. 동일 날짜의 lotId 정렬, N=0, 잘못된 값 거부도 관찰 가능한 조건으로 제시한다.
6. 전체 요구 ID 커버리지와 의존성을 유지하며, 모델이 실행할 검증 명령 정책·담당자·실행 결과·승인을 생성하지 않는다. 실제 제품 구현과 팀원 실행은 계속 보류한다.
