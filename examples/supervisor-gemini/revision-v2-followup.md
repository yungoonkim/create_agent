사용자의 v1 수정 요청을 마무리하기 위한 인수시험 진행자의 후속 점검이다. 새 요구나 Scope 변경 요청이 아니다.

숫자 문자열 검증과 안전 정수 검증을 분리한 v2의 개선을 유지한다. 저장 JSON의 필드 검증뿐 아니라 로드한 전체 목록에서 중복 lotId도 거부하도록 명시하고, 루트 저장 구조도 하나로 명확히 정한다.

아직 불충분한 '원자적 저장의 보장 범위와 실패 처리'를 다음과 같이 정확히 구분한다.
- 같은 파일시스템의 원자적 rename은 부분 JSON 노출 방지에 관한 가정이며 모든 플랫폼·파일시스템에서 전원 장애 뒤 영구 보존을 보장하지 않는다. 임시 파일 fsync만으로 부모 디렉터리 변경까지 영구 반영됐다고 단정하지 않는다. 지원 환경의 디렉터리 fsync와 이식성 한계를 설명한다.
- rename 이전 쓰기/fsync/교체 실패와 rename 성공 이후 디렉터리 동기화 실패를 구분한다. 후자에는 새 본파일이 이미 보일 수 있으므로 '오류면 항상 원본 파일 불변'이라고 약속하지 않고, 저장 결과 불확실성을 오류로 보고하며 임의 초기화·되돌리기·재덮어쓰기를 하지 않는다.
- catch 가능한 오류에서 임시 파일 삭제는 최선 노력이며 cleanup 자체도 실패할 수 있다. 원래 오류를 보존하고 정리 실패를 별도 보고한다. SIGKILL·전원 단절 시 finally나 cleanup 실행을 보장하지 않는다.
- 비정상 종료 뒤 임시 파일이 남을 수 있다. 다음 시작은 본파일을 검증해서 사용하고 임시 파일을 자동으로 본파일로 승격하지 않는다.
- 이 경계별로 관찰 가능한 검사 사례를 명시한다. 실제 전원 단절 실험을 실행하지 않았는데 통과·무손실이 증명됐다고 쓰지 않는다.

승인된 lot·수량·날짜 규칙과 제외 범위를 유지하고, 실제 제품 구현이나 팀원 실행은 하지 않는다.
